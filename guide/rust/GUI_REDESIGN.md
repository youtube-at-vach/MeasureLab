# Rust GUI再設計計画

## 目的と状態

**計器を選べば、その計器を使える。複数の計器を見たいときだけ、明示的に並べる。** この操作をRust版の基本にする。全機能の表示ON／OFFと全設定の一覧を利用者に管理させる構成から、目的の計器を中心にした構成へ変更する。

本書は実装の操作契約と実装順序を定める。G0〜G3の表示モデル・単独表示・コンソール・設定移行と、G4のイベント操作回帰・内部／指定した外部経路の統合QA・現行操作文書を実装した。配置の寸法判定と描画を共通化し、区画内の追加詳細はスクロールで扱う。前面のメニュー・編集画面を操作しても背後の区画へ選択を移さない。再実行の入口と確認範囲は [VALIDATION](VALIDATION.md#gui入出力qaの再実行) に置く。

G4の実装・自動統合確認・文書更新は完了した。Metalの遮蔽による撮影停止にはQAウィンドウの前面保持で対処し、内部経路、BlackHole 2ch／16ch、UAC-232の撮影・独立数値照合・保持・保存・別プロセス復元・再測定を確認した。QA出力は通常の入出力と同じバッファ要求を使い、CoreAudioで共有される設定の変更競合を避ける。

通常ビルドの手動操作と実モニター間DPI切り替えは、操作可能な環境で対象名・主要値・状態・停止操作、構成保持を確認する。**現在のIntel Macでは技術的に実施できない手動GUI操作チェックを検証計画から除外し、公開前の未完了条件に数えない。** 実行可能な自動QAは継続し、対象外を他環境の確認済みへ読み替えない。物理経路の確認は利用した機器・Fs・接続条件に限定し、最大Fs・再接続・長時間の評価を代用しない。今後の計画見直しと新しい測定機能は、このGUI改修の区切りから分ける。現在の操作説明は [README](README.md)、測定上の不変条件は [現在の方針](../CURRENT_DIRECTION.md)、開発全体の優先順は [PLAN](PLAN.md) を正本とする。ここでいう「単独表示」は、Scopeのトリガーモード`Single`とは別の表示状態を指す。

最初の対象は現在実装済みのScope、Spectrum、Spectrogram、XY、Lock-in、同期2ch比較、Generator。2ch測定の使いやすさを先に完成させ、1〜16chの入力・割当は維持する。

## 改修前の問題と変更方針

改修前のRustコードとPython最終版の文書・`v0.9.1`のソースを確認して設計を整理した。新GUIの自動操作・状態遷移・画像確認の入口は [VALIDATION](VALIDATION.md) に置き、通常ビルドの手動操作と実モニター間DPI切り替えは同文書の対象環境に従う。

| 問題 | 改修前の根拠 | 変更方針 |
| --- | --- | --- |
| 使いたい計器を押しても、既存の計器を消す作業が残る | `app.rs`の表示ボタンは各`visible`を反転。通常起動はScope＋Spectrum | 計器選択は単独表示への遷移。同じ計器を再選択しても状態を変えない |
| 同じ目的の入口が増えている | 個別表示トグルと`view_menu()`の組合せプリセットが併存 | 計器選択、コンソールへの追加、配置変更に役割を分ける |
| 設定一覧が機能数に比例して長くなる | `SettingsSection::ALL`の10項目を`controls()`がアコーディオン表示 | 選択中の計器だけを扱う詳細欄と、共通の入出力設定に分ける |
| 各パネルにSettingsが反復し、設定への移動場所も異なる | `instrument_settings()`、GeneratorのSettings／I/O、Lock-inのSettings／Input／REF設定 | パネル選択に詳細欄が追従。共通設定の入口は上部へ集約 |
| 画面上部が操作と対象を十分に伝えていない | 大きなアプリ名・サブタイトル、別行の出力バー、中央の表示ボタン群 | アプリ名はタイトルバーに残し、メニューと入出力状態・操作を共通ヘッダー1行にまとめる。開始／停止を右端へ置く |
| 表示と実行の関係を推測する必要がある | Lock-in／Comparisonは表示フラグと解析の`enabled`が独立 | 選択中、表示中、解析中、出力中を区別し、実行中の処理は画面外でも分かるようにする |
| Generatorだけ配置方法が異なる | 中央領域の先頭へ描画し、他の計器グリッドとは別扱い | 表示上は他の計器と同じ区画として配置。出力の実行状態は独立して維持 |

表示状態は [presentation.rs](../../src/presentation.rs)、共通枠は [shell.rs](../../src/app/shell.rs)。計器の入口は [app.rs](../../src/app.rs)、[Generator](../../src/app/generator_panel.rs)、[Lock-in](../../src/app/lockin_panel.rs)、[同期比較](../../src/app/comparison_panel.rs)、[保存形式](../../src/settings.rs)。

## Python版から引き継ぐ考え方

[計測コンソール](../../docs/widgets/measurement_console.md)と通常ページの役割分担を参考にする。

* 名前を選んで一つの計器を使う。並列表示は明示的な追加操作にする。
* 単独表示とコンソールは同じ計器の設定・結果・実行状態を参照し、解析器を重複生成しない。
* 配置を変えても測定条件と測定の進行を保持する。
* 構成の保存、狭い画面でのタブ表示、実行状態の表示を用意する。

Rust版では、通常画面と別ウィンドウのコンソールを往復させず、同じアプリ画面で単独表示／コンソールを切り替える。Python版にあった多数のドッキングプリセット、同じボタンの再押下による順送り、分離ウィンドウ、表示と操作部の分割は初回の対象に含めない。

## 画面構成

広い画面の構成案。文言・寸法・装飾は操作試作で調整する。

```text
┌ メニュー ──────── 出力: OFF [停止]   入力: 停止 [開始] ────┐
├ 計器 ──────────┬──────────────────────┬ 選択中の詳細 ──────┤
│ 観察            │ Scope       [並べる…] │ Scope              │
│   Scope         │ CH / 時間軸 / 振幅    │ トリガー条件       │
│   Spectrum      │                      │ 取得モード         │
│   Spectrogram   │ 波形と主要数値        │ その他の詳細       │
│   XY            │                      │                    │
│ 解析            │                      │                    │
│   Lock-in       │                      │                    │
│   同期2ch比較   │                      │                    │
│ 信号生成        │                      │                    │
│   Generator     │                      │                    │
│ 計測コンソール  │                      │                    │
├────────────────┴──────────────────────┴────────────────────┤
│ 公称Fs / 入力CH / 欠落 / 校正状態 / 保存結果の通知            │
└─────────────────────────────────────────────────────────────┘
```

* **上部：アプリ共通の操作。** 左にファイル、表示、入出力、ヘルプ、実行一覧、右に出力の状態・停止、入力の状態・開始／停止を1行で置く。入力の開始／停止を右端に固定し、アプリ名はウィンドウタイトルだけに残す。狭幅ではメニューをMenuにまとめ、状態の接頭辞をIN／OUTに短縮する。
* **左：計器の選択。** 通常表示はアイコン＋名称と実行状態を扱い、名称・用途で検索できる。上部ボタンで固定幅のアイコン列へ切り替え、プロットへ幅を返す。コンパクト表示は検索に関係なく7計器を固定順序で並べ、選択背景と実行状態の点を分ける。名称・状態はツールチップ、最下部はコンソールへの入口とする。装飾やアニメーションは追加しない。
* **中央：測定・生成の作業。** 一つの計器を広く表示する。計器名、取得状態、有効性、主要数値、頻繁に使う操作を同じ領域に置く。
* **右：選択中の計器の詳細。** 一つだけ置き、対象名を常に表示する。単独表示ではその計器、コンソールでは選択した区画に追従する。ホバーだけで編集対象を変えない。
* **下部：共通の状態と通知。** Fs、CH、欠落、保存・読み込み結果など。通知は理由と対象を表示し、長い設定一覧のスクロール位置へ飛ばさない。

常設の3列をすべての幅へ押し込まない。狭幅では計器一覧を名前付きの選択メニューへ縮め、詳細は中央領域の「測定／詳細」切り替えで扱う。取得・出力状態と停止操作は残し、測定画面を設定で覆うことを標準にしない。

サイドバーの表示モードだけをeframeのアプリ保存領域へ自動保存し、次回起動に復元する。狭幅への退避は保存モードを上書きせず、Viewメニューからも変更できる。測定設定・結果形式と分離し、取得・解析・生成へのコマンドを伴わない。`--ui-smoke`は利用者の表示モードを読み書きしない。

### macOS標準メニューバーへの移行案（未実装）

macOSでは画面上端の標準メニューバーへアプリ共通メニューを移し、ウィンドウ内には入出力状態・開始／停止の1行を残す方針を候補とする。Windows／Linuxはアプリ内メニューを継続する。今回のヘッダー整理にはネイティブメニューの実装を含めない。

* **メニュー構成。** MeasureLab（About／Services／Hide／Quit）、File、Edit、View、I/O、Instrument、Running、Window、Helpを候補とする。File／I/O／計器選択／解析停止は既存の操作へ接続する。Editのコピー・貼り付け・取り消しはeguiの編集中項目へ適切に渡し、Windowの最小化などは標準動作を使う。Viewの分割比率・表示倍率はネイティブメニュー内のスライダーではなく、値を編集する画面への入口にする。
* **実装境界。** 先にメニューの操作要求・選択状態・有効条件をegui描画から分離する。macOSのメインスレッドでAppKitのNSMenuを生成・更新し、選択イベントはUIへ渡して既存の操作要求を呼び、停止中の描画も起こす。Audio I/O・測定・生成ワーカーへメニューから直接触らない。
* **技術候補。** 現行eframeのmacOS実装も利用する`objc2-app-kit`での直接連携を第一候補として、小さなFile／Helpメニューで初期化・寿命・イベント受信を確認する。[muda](https://docs.rs/muda/latest/muda/)もNSApplicationへのメニュー登録・イベント受信を提供する比較候補。依存追加はmacOSのdesktop機能へ限定し、MSRVとGUIなしビルドを維持する。既存のアプリメニュー・Servicesを壊さず統合できることを選定条件にする。
* **操作の整合。** Cmdによる標準操作と既存ショートカットの対応を決め、1回のキー入力がネイティブとeguiで二重実行されないようにする。入力編集中・前面ウィンドウ・メニュー操作中の優先順位、復元やデバイス変更の有効条件、選択中の計器・配置のチェック表示を共通状態へ同期する。
* **移行の完了条件。** メニュー選択・無効化・ショートカット・停止中の再描画・終了時の入出力停止を確認し、メニューを開いている間も取得・解析・生成が継続することを検証する。macOSで標準メニューが成立した段階でウィンドウ内の重複メニューを除去する。AppKitの実連携と他OSの回帰を確認するまでは未実装として扱い、操作可能な環境での手動確認と自動QAを区別する。

標準メニューバーの役割は[Appleの設計ガイド](https://developer.apple.com/design/human-interface-guidelines/the-menu-bar)、AppKitの登録先は[NSApplication.mainMenu](https://developer.apple.com/documentation/appkit/nsapplication/mainmenu)を参照する。メニューのウィンドウ外への移動と、ウィンドウのタイトルバー統合は別の判断とする。

## 操作の契約

### 単独表示とコンソール

| 操作 | 結果 |
| --- | --- |
| 左の計器名を選ぶ | 常にその計器の単独表示へ移る。コンソールの構成は別に保持する |
| 選択中の計器名を再度押す | 何も解除せず、その計器を維持する |
| 単独表示の「並べる…」で別の計器を選ぶ | 現在の計器と選んだ計器の2計器をコンソールで表示する。既存構成を置き換える場合は選択画面で示し、直前の構成へ戻せるようにする |
| 「計測コンソール」を選ぶ | 保持中の構成と選択区画を表示する。未作成なら用途説明と「計器を追加」を表示する |
| コンソールで「計器を追加」 | 一つ追加する。既存の計器は選択するだけで、複製しない |
| 区画をクリック／キーボードで選択 | その区画の選択枠と詳細欄の対象を変える。配置は変えない |
| 区画の「単独表示」 | その計器を単独表示する。コンソール構成は保持し、戻れる |
| 区画の「表示から外す」 | コンソールの構成だけから外す。解析・出力の停止は行わない |
| 「左右」「上下」「2×2」「タブ」を選ぶ | 指定した配置にする。同じ配置を再選択しても順送り・反転しない |

初回起動は入力・出力停止のScope単独表示にする。明示的な設定復元では保存された単独表示／コンソールを復元する。サイドバーの表示モードを除くレイアウトの起動時自動復元や、名前付き構成の管理は後続に分け、初回から別の保存体系を増やさない。

コンソールの第一段階は2計器、続いて4区画とタブを扱う。現在の7計器すべてを構成に保持でき、区画数を超えた分は名前付きタブで選ぶ。Generatorも同じ仕組みを使う。初回は各計器1個で、複数Spectrumなど独立設定を持つ同種計器の多重起動は扱わない。

既存の構成へ足したいときは「計測コンソール」→「計器を追加」を使う。単独表示から2計器を並べる操作で、以前の不要な計器が自動的に復活することを避ける。追加した計器は選択・表示し、選択中の区画を外したら隣の計器へ選択を移す。最後の計器を外した場合は、説明と追加操作のある空のコンソールにする。

狭幅ではタブ表示へ退避し、その理由を短く表示する。広幅へ戻すと選択済み配置を復元する。希望配置と実際の表示配置を別に保持し、サイズ変更で保存した構成や比率を上書きしない。区画の最小寸法と各計器の操作量から切り替えを判断し、重要な数値や停止操作を画面外へ押し出さない。

### 設定の置き場所

設定へのジャンプボタンを増やさず、設定の責務ごとに編集場所を決める。同じ項目の編集UIを主要操作列と詳細欄の両方へ重複配置しない。捕捉済み条件の読み取り専用表示は残す。

| 対象 | 編集場所 |
| --- | --- |
| ScopeのCH選択、表示ON/OFF、倍率の概要 | 波形直下の高さ40ptの4chバー。選択・可視・入力の有無を独立に扱う |
| Scopeの取得、時間軸・水平位置・Autoset、トリガー、選択CHのレンジ・オフセット・Fit・入力割当 | 詳細欄のAcquisition／Horizontal／Trigger／Channel |
| SpectrumのCH、表示範囲、カーソル | Spectrumの主要操作列・プロット |
| SpectrumのFFT点数、窓、平均、更新モードなど | 選択中の詳細 |
| SpectrogramのCHと頻用する表示操作 | 計器の主要操作列。解析条件は選択中の詳細 |
| XYの入力CH・観察時間・両軸の振幅範囲・カーソルモード | 詳細欄のObservation／X Axis／Y Axis／Cursors。Trace SnapではScopeと共通のTriggerも編集。A／B選択・Clear・読み値はプロット側 |
| Lock-in／同期比較のREF・SIG、解析開始／停止 | 各計器の主要操作列。フィルター、窓、平均などは選択中の詳細 |
| Generatorの周波数・振幅・位相、信号の有効状態、出力開始 | Generator本体。波形・OUT選択・カード管理も本体、刻み幅・seed・実適用値は選択中の詳細 |
| 入力・出力デバイス、Fs、出力CH割当、Software Loopback、CH校正 | 上部の「入出力」から開く共通設定。「入力／出力／校正」で整理 |
| 設定保存・復元、保持結果の保存・読込・参照比較 | 「ファイル」。同期2ch比較の計器と、保存結果の比較を別の名前で示す |
| 配置、詳細欄の表示、表示倍率 | 「表示」。計器を選ぶ役割は持たせない |
| 単位の説明、ショートカット、診断情報 | 「ヘルプ」 |

各計器のSettingsボタン、Lock-inのInputボタン、Generator内のI/Oボタン、全計器を列挙する設定アコーディオン、組合せ名を列挙したViewメニューを廃止する。詳細欄の表示／非表示は共通位置の一操作にする。

入出力設定を閉じると元の計器・選択区画へ戻る。エラーからの誘導が必要な場合も、この共通画面の該当タブを使う。入力変更による新世代への再取得、停止中の次回条件、出力先の変更制約は現行の契約を維持する。

カーソル操作は対象計器内へ移す。既存のScope時間参照など計器間の連動は維持し、どの計器・軸を操作しているかを表示する。

### 表示選択と実行状態

**計器を選ぶ操作は表示を変える。取得・解析・生成の開始／停止は、対象を明示した操作で行う。** これを分けたうえで、実行操作を設定の奥へ隠さない。

* 共通バーの「入力開始／入力停止」は共通入力を扱う。入力停止で出力まで停止したと解釈できる`Stop`単独の文言を避ける。
* Lock-in／同期比較の解析有効化は、設定内のチェックボックスから計器本体の「解析開始／解析停止」へ移す。入力停止中は「入力待ち」を示す。選ぶだけで取得やGenerator出力を始めない。
* Generatorの出力開始はGenerator本体に置く。出力状態・出力停止は共通バーに常設し、単独表示・コンソール・設定画面のどこでも確認・停止できる。
* 画面から外した計器の解析・平均・保持を終了させない。選択を示す強調と、実行中を示す文字・印を区別する。共通バーの実行一覧から非表示の解析対象も確認・停止できるようにする。
* 初回改修では現行Scope／Spectrum／STFT等の実行方針を維持する。未使用解析の起動・解放最適化は、明示的な実行要求と利用先の管理を定義する別工程とし、表示フラグで停止を決めない。
* 配置・表示変更で入力世代、解析設定、平均窓、整定、Generator位相・出力、保持結果を変更しない。設定復元では既存と同様に入力・出力を停止状態に保つ。

パネルには取得状態（LIVE／HELD／WAITING等）と測定上の有効性（REF不足、欠落、未校正等）を引き続き分けて表示する。詳細欄の次回設定で保持結果の条件を書き換えない。

## 実装境界

表示モデルを先に整理し、egui／eframe・wgpuと既存の測定ワーカーを継続利用する。大きなGUI変更をDSPの書き直しと同時に進めない。

| 境界 | 変更案 |
| --- | --- |
| 計器の識別 | Generatorを含む共通の`InstrumentId`と、名称・分類・描画・詳細の対応表。動的プラグイン機構は導入しない |
| 画面状態 | `Single(InstrumentId)`／`Console`、コンソール内の計器順、選択区画、希望配置・比率、詳細欄の表示を一つのモデルへ集約。構成置換の取消用に直前の構成をセッション内で保持 |
| 操作 | `OpenSingle`、`AddToConsole`、`FocusPane`、`RemoveFromConsole`、`SetLayout`など、目的が一意の操作として処理する |
| アプリ枠 | ヘッダー、計器一覧、詳細欄、コンソール配置を`src/app/`内の専用モジュールへ分離 |
| 計器表示 | 単独／コンソールで同じパネルを描画する。既存`generator_panel.rs`等を継続し、`app.rs`内のScope等も段階的に分離 |
| 実行制御 | 既存の取得・解析・生成コマンドを共通の呼出し口へ接続。配置変更がコマンドを発行しないことを検証 |
| 保存 | `settings.rs`の測定条件と表示状態の分離を維持して新しい表示モデルを保存。`results.rs`等の結果形式へ配置を混ぜない |

旧`visible: [bool; 4]`、個別の表示フラグ、`previous_view`、`Sidebar.section`は`presentation.rs`の表示モデルと`app/shell.rs`の共通枠へ置き換えた。旧フラグと新モデルを二重の正本として長期維持しない。`app/workspace.rs`は現在ファイル操作・結果比較を含むため、新レイアウトの状態管理を単にそこへ追加せず責務を分ける。

### 設定ファイルの移行

現行の設定形式はversion 5。version 1〜4を読む移行処理と新形式の往復検証を`settings.rs`に置く。旧ファイルは保存操作まで書き換えない。

* 旧設定で一つだけ表示される場合は、その計器の単独表示へ変換する。
* 複数表示は同じ計器のコンソールへ変換する。旧画面の順序（Generator、Scope、Spectrum、Spectrogram、XY、Lock-in、Comparisonのうち表示対象）と対応可能な配置を保持する。
* 旧形式に選択区画がない場合は、変換した表示順の先頭を選ぶ。詳細欄の表示は旧サイドバーの表示設定から移す。
* 解析の有効状態、CH、Fs、校正、表示軸、Generator条件は表示移行と独立して引き継ぐ。復元によって入出力を開始しない。
* 未知の形式・不正な測定条件は現行の検証方針どおり拒否し、部分適用しない。測定条件が正常で画面寸法・配置だけ復元できない場合に限り、見える単独表示／タブへ退避する。
* 旧設定ファイルを読み込んだだけでは上書きしない。保存操作で新形式を書き出す。旧版アプリが新形式を読めるとは保証しない。

## 実装順序と完了条件

| 段階 | 成果物 | 次へ進む条件 |
| --- | --- | --- |
| G0：操作試作 | 単独Scope、単独Lock-in、Scope＋Generator、Scope＋Spectrum、入出力設定の試作。通常幅と狭幅 | 計器選択・並べる・設定編集・停止の一連操作を試し、操作の意味と主要操作の置き場所を確定 |
| G1：表示状態の分離 | 新しい表示モデル、明示的な操作、旧設定の移行と保存 | 再選択が解除にならず、表示操作が取得・解析・出力状態を変えないことをコードで確認 |
| G2：単独表示の完成 | 新ヘッダー、計器一覧、選択中の詳細、7計器の主要操作、共通入出力画面 | 全計器へ直接到達でき、旧トグル列・設定一覧・重複ジャンプを撤去。非表示の実行状態と出力停止も確認可能 |
| G3：必要時の並列表示 | 2計器から4区画・タブまでのコンソール、選択追従、追加・除去、狭幅退避 | 単独との往復で構成と測定が保持され、Generatorも同じ配置操作で扱える |
| G4：統合・文書更新 | GUIの操作回帰、内部／外部経路の関連QA、現行操作マニュアルの更新 | 既存の保持・保存・復元・再測定が成立し、段階4.5／5の統合評価を新GUIで実行できる |

G0は見た目の画像だけで完了させず、クリック順と状態の変化を確認できる試作にする。G1以降はレビュー可能な単位へ分けるが、G2だけで新GUIの完成とはしない。既存設定の複数表示は移行途中も保持し、G3の実装へ引き渡す。

実装ではG2／G3の操作モデルを新規測定機能より先に整える。段階4.5／5の数値・機器評価は継続できるが、通常GUIの最終受け入れはG4の新画面で行う。段階6の測定フローは、手動計器・入出力の所有権とこの画面構成を接続できる状態になってから進める。未実装フローの空メニューは先に増やさない。

## 受け入れで確認する操作

以下は実装時にテスト・QAへ落とすシナリオ。具体的な試験条件・寸法・許容差・合否はコードを正本とし、本書へ試験結果を蓄積しない。

* ScopeからSpectrumを選び、不要な計器を消す操作なしでSpectrum単独になる。同じ項目を再選択しても空画面にならない。
* ScopeにGeneratorを並べ、Generatorを選択して編集し、Scope単独へ戻り、コンソールへ戻る。信号・設定・構成を失わず、出力中と出力停止が常に分かる。
* 並列表示で片方を選ぶと、その計器名と詳細が対応する。テキスト入力中のホバーで対象が変わらず、プロット操作も正しい計器へ届く。
* Lock-in／同期比較を選ぶと解析の停止・入力待ち・整定・有効性を区別でき、解析開始を設定内から探す必要がない。
* 入力停止後もGenerator出力中であることが分かり、表示からGeneratorを外した後にも共通バーで停止できる。
* 非表示の連続解析、平均、整定、Scope Singleの有限取得、UI停止時の入出力継続が従来の契約を満たす。
* 保持中に次回設定を編集し、設定・結果の保存、旧設定復元、参照比較、再測定を行っても、捕捉済み条件と数値が改変されない。
* 通常幅・既存の最小ウィンドウ付近・表示倍率変更で、対象名・主要値・状態・停止操作を読める。狭幅への往復でコンソール構成が消えない。
* キーボードで計器選択・区画移動・詳細編集・元の画面への復帰ができる。入力欄編集中のSpaceが共通入力を開始／停止しない。選択・実行・異常は色だけに依存しない。

Rust変更時は [共通検証](../../.agents/workflows/tool_usage.md) のfmt、全ターゲット・全機能Clippy／テスト、GUIなし・通常テスト、デスクトップビルドを実行する。[VALIDATION](VALIDATION.md) のGUI QAを新操作に合わせ、画像確認だけでなく操作イベントと状態遷移を検証する。UI構成ごとにDSPテストを重複実装せず、既存の数値テストと必要な統合QAを使う。公開マニュアル変更時はMkDocsビルドも実行する。

初回実装では自由ドッキング、独立ウィンドウ、同種計器の複製、スキン、新しい測定機能を追加しない。基本操作の受け入れ後に、実際の測定用途から必要なものを選ぶ。
