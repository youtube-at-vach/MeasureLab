## 現在の実行構造と残る境界

```text
CPAL callback → 固定容量SPSC → 測定ワーカー ← Software Loopback／QAデモ
                                ├→ 共通f64履歴・Scopeトリガー・生サンプル統計
                                ├→ 選択CH転送 → Spectrumワーカー
                                ├→ 同期2ch転送 → Lock-inワーカー
                                └→ 固定容量転送 → STFTワーカー
各ワーカー → 世代・整数区間・条件付き結果 → UI表示／保持／非同期ファイルI/O
```

入力・解析の欠落と表示更新の省略を区別する。UI停止・非表示で解析・平均を止めず、Stopは有限の入力終端を処理してから保持する。遅着・旧世代の結果を混ぜない。Scope捕捉区間とSpectrum窓を同時刻と誤認させず、不足区間をゼロ埋めして取得済みにしない。

SpectrumのContinuousはN/4の全窓、Live／Latestは最新窓の観察で、後者は過渡捕捉を保証しない。48 kHz・512kの完全窓は約10.92秒。更新頻度・Δf・RBW・窓時間・平均の整定を区別し、f64の基準経路を維持する。

### 4：Software LoopbackとLock-inによる品質評価

今回の対象OSはmacOSとする。Windows／Linuxの実機・GPU・音声I/O・長時間性能・設定復元は後続タスクへ送る。今回の条件・成功・失敗・途中終了の区別は [macOS統合評価](validation/STAGE4_MACOS_2026-10.md) に保持する。

| 範囲 | 今回の判定と根拠 |
| --- | --- |
| 4a：仮想系・境界・結果再利用 | 内部数値回帰、可変長コールバック・世代・有限終端・欠落、Software Loopbackの保存復元・再測定・Singleを確認。通常幅／狭幅の比較画像を受信 |
| 4b：外部I/O・物理Lock-in | BlackHoleとUAC-232の条件付き数値照合・保存復元を確認。UAC-232の通常GUIで独立生入力照合・別プロセス再測定・比較画像を確認。同一ワーカーの48→96→44.1→192 kHz→BlackHole→UAC-232を確認 |
| 4c：512k・実行分離・負荷 | BlackHole 16ch・96 kHz・512k Continuousの30秒で予定20窓・入力／解析欠落0。UAC-232・48 kHz・4表示・512kで8.192秒のUI停止中も取得／解析が継続し、30秒の有限結果を照合。長時間は中断まで約270秒・95窓・捕捉欠落0を確認し、ユーザーが今回の時間として受け入れた。600秒完走・最終有限結果の照合とは扱わない |
| 4d：確認範囲の確定 | 操作ガイドと公開マニュアルへ条件・制限を反映。macOSの未校正FS・公称Fsの2ch測定用途として今回の段階4を完了。段階5、main移行・タグ・公開は進めない |

基本波Lock-inの定義・許容差は [Lock-in検証](validation/LOCKIN_2026-10.md)、入力世代・可変長・Stop／Singleの境界は [入力境界](validation/CAPTURE_BOUNDARIES_2026-10.md)、保存形式と条件付き比較は [結果再利用](validation/LOCKIN_RESULTS_2026-10.md) を参照する。過去の [BlackHole](validation/BLACKHOLE_LOCKIN_2026-10.md)／[UAC-232](validation/UAC232_LOCKIN_2026-10.md) のGUIなし600秒成功は、今回のGUI約270秒と分ける。

入力・解析の欠落と表示更新の省略を区別する。出力の接続時通知はQAの明示的な0.5秒区間だけを別記録し、測定中の出力失敗とすべての入力失敗を無視しない。BlackHole 16chの通常GUI再接続で入力通知による失敗を観測し、起動安定性の保証は残す。Singleの未充填FFTやLock-inの整定状態を正常値へ置き換えない。

512kの同じ整数窓終端から解析完了・UI描画提出までの遅延を直接計測する。CPU上の入力利用可能時刻を基準にし、p95の差や合計で代用しない。UI間隔約16.7 ms、フレームCPU約4 ms、Continuousの解析p95がhopの25%以下、512k Latestが25 ms以下を比較の目安として維持する。今回の短時間測定で目安との差を記録し、全条件の性能保証にしない。

**後続へ保持する境界：**

* UAC-232の−40 dB応答では高レベル時から約0.11〜0.16°の位相変化を観測した。同じ実入力窓との演算一致は確認できたが、原因・CH間校正・外部電圧基準・広帯域／絶対遅延・実Fsは未確認。
* 外部I/Oの実コールバックは512フレーム固定。内部の可変長回帰を外部I/Oの可変長確認に置き換えない。物理16ch・他機器も未確認。
* 接続直後の短い外部Single、入力起動通知後の通常GUI回復、すべてのFsでの通常GUI長時間安定性は今回の受け入れ保証に含めない。
* 反復操作要求→状態表示のp95 100 ms以下の確認、GPU実行時間、ADC時刻と実表示／scanout、全構成の600秒評価は未確認。約270秒の途中終了時は最終有限結果と完了時の通知監査が未実施。
* Windows／Linuxの実機確認は後続タスクとする。今回のmacOS確認を各OSの保証へ広げない。

### 4.5：シグナルジェネレーターの基本実装

**完了条件：GUIから周波数・振幅・位相を設定して正確な信号を発生でき、MeasureLab内の測定器で観測できること。** 内部のf64照合と通常版の外部出力の確認を別々に必須とし、公称Fs・未校正FSの保証範囲を示す。

### 5：同期2chの比較測定

最初の用途は、同じ入力時計の2chに対するゲイン・位相・遅延の比較とする。段階4.5を先に完成させて統合検証の励振に使うが、外部信号でも測定できる入力側の解析として実装する。Generator追加で顕在化した重大な精度・欠落問題は着手前に解消する。

* 同じ整数区間・窓の複素クロススペクトル、各CHの自己スペクトル、平均とコヒーレンスを定義する。位相・遅延の符号、ゼロ入力、相関のない雑音、欠落・CH変更時の無効化を先に決める。
* 共有演算は入力世代・時計・区間・CH・窓・精度・校正・解析条件が一致する範囲だけに限定する。汎用計算グラフを先行実装しない。
* 既知のゲイン・位相・整数／分数遅延・雑音・フィルターで理論値と照合する。CH間の振幅・位相校正が未確認なら、その制限を数値・保存結果に残す。
* 表示だけでなく、停止・条件付き保存・読み戻し・再測定まで完成させる。Scope／Spectrum／Lock-inと1〜16ch基盤を回帰確認する。

### 6：最小の応答測定フロー

段階4.5で完成したGeneratorの開始・停止・レベル制限・切断処理と、段階5の同期比較を使い、2ch REF／応答による最小FRF／Bode用途を作る。基本出力の再実装は行わない。

* 出力と取得の所有権を測定フローへ明示的に渡し、手動操作との競合と終了・失敗時の停止を定義する。設定復元だけで出力を開始しない。段階4.5の入出力デバイス・時計・遅延・欠落の識別を継承する。
* 周波数点ごとの励振・整定・取得を制御する最小構成から始める。信号生成→仮想DUT→共通入力→解析の経路を先に検証し、外部ループバック・物理系で既知ゲインとフィルター応答を照合する。連続スイープは別途定義する。
* 測定フローは開始・停止・完了・失敗と条件付き結果を持つ。励振、解析帯域、整定、校正、保存・再実行までを完了条件とする。
* THD／THD+N・IRや複数の測定器は同時に追加せず、最小FRFが成立してから個別に計画化する。
