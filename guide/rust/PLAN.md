# MeasureLab Rust 開発計画

Generatorで励振し、同期2chで応答を測り、結果を保存・再利用できるところまで仕上げる。[現在の方針](../CURRENT_DIRECTION.md) の実行分離・f64基準・1〜16ch同期入力を維持し、初回`v0.10.0`は実験段階のPrereleaseとする。

この文書は次の作業と着手条件だけを保持する。操作・実装の入口は [README](README.md)、検証手順・実機確認範囲は [VALIDATION](VALIDATION.md)、配布条件は [公開準備](RELEASE_PREPARATION.md) を正本とし、完了した機能別計画は残さない。

初回プロトタイプまでの残作業・成果物・完了条件は [公開準備のタスク一覧](RELEASE_PREPARATION.md#初回プロトタイプ配布前のタスク) を正本とし、進行中の実装とは別に管理する。エージェントのアプリ検証はmacOS（Intel）に集中する。Windows・Linuxの確認はユーザーが行い、エージェントは不具合報告時だけ該当条件を調査する。以下に残る他OS・機器・操作の評価項目を、エージェントによる全OS再試験や初回公開の追加条件へ読み替えない。Apple Siliconの実機確認も今回のエージェント作業には含めない。

## 現在地と次の作業

GUI再設計G0〜G4の実装・自動統合確認、Spectrogram S1〜S6、Cepstrogram C1〜C4、初回翻訳と視覚レビューI1〜I6は完了した。Generator・同期2ch比較（段階4.5／5）は代表48 kHzの内部・BlackHole 2ch／16ch・UAC-232で、通常Generatorの保存→別プロセスOFF復元→明示Start→再測定・独立Stop・JSON／CSVと同じ入力窓の独立照合を確認した。次は配布候補を受け入れる。確認したソース・機器・条件は [実機確認の要約](VALIDATION.md#コードで代替できない確認の要約) を参照する。

| 順序 | 作業 | 完了条件 |
| --- | --- | --- |
| 1 | 配布候補の短い通し確認 | 同一候補SHAの通常release／desktop・qaなしで、入出力選択→測定→独立停止→保存→再起動・OFF復元を確認する。公開前の必須条件は [最小確認セット](RELEASE_PREPARATION.md#公開前の最小確認セット) に集約する |
| 2 | 公開準備を仕上げる | 必須CI・最終配布物・文書と既知の制限を照合する。タグ・Release・サイト公開は依頼された段階で進める |

UAC-232の配線はLL TRS／RR XLR（−20 dB）を代表条件とする。停止・解放後の再接続と、模擬通知によるERROR保持・出力解放は別に判定する。測定・出力中のUSB抜去は行わない。[実機確認の要約](VALIDATION.md#コードで代替できない確認の要約)

## 検証の範囲

- 変更した挙動と回帰リスクに合わせて検証する。Rust変更・PR時の [共通チェック](../../.agents/workflows/tool_usage.md#rust-アプリ) は維持し、不具合は回帰テストで固定する。
- カード操作・各波形・REF／SIG交換・低REF／欠落・保存形式の条件は既存の自動テストと機能別QAを使う。同じソース・機能構成・条件の証拠は再利用し、変更の影響がない全経路・全波形の実機試験を繰り返さない。
- 通常GUIは主要値・単位・無効理由・停止操作と保存復元を短く通す。全メニュー・全配色の網羅、反復撮影、600秒試験、繰り返し再接続は、不具合調査や関連変更で必要になったときだけ追加する。
- 精度・継続性の開発QAと配布物の起動・操作確認は目的を分け、数値試験一式を各OS・CPU・配布形式で重複実行しない。確認できない環境は制限を明記し、未実施を合格にしない。

## 初回配布と分ける課題

以下は確認範囲を明記して残す後続課題とし、初回配布の一律の必須条件にしない。

| 対象 | 残る範囲 |
| --- | --- |
| 高Fs・多ch・高負荷 | UAC-232の192 kHz起動時STFT欠落、物理4〜16ch、768 kHz・CPU競合下の取得／解析欠落。768 kHzは設定上限で、無欠落動作の保証ではない |
| GUI・表示応答 | 実モニター間DPI、実表示遅延、最大設定・ディスクI/O負荷。現在のIntel Macの手動GUI・実モニター間DPIは対象外とし、操作可能な環境で必要な範囲を確認する |
| 物理校正 | 実時計・物理振幅・CH間位相・出力・DAC／ADC絶対遅延。公称Fs・未校正FSを維持し、UAC-232小信号の位相変化は原因未確定とする |
| 保存の拡張 | Spectrogram／XY・カーソル・全CH長時間記録・Spectrum全生入力。現行の保存範囲は [README](README.md#保持結果の書き出し) を参照する |

## 後続の開発

### 6：最小の応答測定フロー（未着手）

基本操作と段階4.5／5の受け入れ後、既存Generatorと同期比較を使って2ch REF／応答の最小FRF／Bodeを作る。初回プロトタイプ配布とは別のマイルストーンとする。

- フローの入出力所有権、手動操作との競合、完了・停止・失敗時の出力停止、復元後の停止状態を定義する。
- 周波数点ごとの励振→整定→取得を作り、既知ゲイン・フィルターを内部→仮想I/O→物理系で照合する。
- 入力区間・校正・欠落・時計を追跡できる結果の保存・再実行までを完了条件とする。

任意波形・スイープ／変調・同期／Mix、ESDとトリガーの連携、時間軸校正、歪み／IR／インピーダンス、外部ADC／MCPなどは、具体的な用途と独立した妥当性検証を用意してから個別に計画する。自由ドッキング・スキン等の表示拡張も、主要値・単位・停止操作を維持できることを着手条件とする。
