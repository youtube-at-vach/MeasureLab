# MeasureLab → 同時に使える測定ワークスペース

添付の `Dream.png` は最終的な方向性の参照画像です。入力・解析・表示を共有する基盤を育て、機能を一つずつ実測で確かめながら追加します。画像中の電圧・dBm・1 MSa/sなどは、現時点の音声入力の仕様を示すものではありません。

## 今回の実装

- 同一の入力履歴からオシロスコープとスペクトルを同時に表示。単独表示も可能。広い画面では左右、狭い画面では上下に配置。
- FFTサイズ 1,024〜32,768、Hann / Blackman-Harris / Rectangular、CH選択、DC除去、指数的な電力平均、ピーク保持。
- 周波数は対数／線形、表示範囲を選択可能。dBFS、ピークのビン周波数、周波数間隔 Δf と窓の等価雑音帯域 RBW を表示。
- 内部デモ信号：正弦波、高調波付き正弦波、帯域制限した矩形波、可変ノイズ。外部への音声出力は行わない。
- 描画パイプラインを共有し、各プロットのGPUバッファ・表示寸法・更新番号を独立させた。FFT計画と作業メモリを再利用。
- オシロスコープの更新とFFTの更新を分けた。FFTは最新の完全な窓を最大30回/秒、かつN/4以上の新規サンプルがあるときだけ解析する。UIへの割り込み処理やバックログを増やさない。

```text
CPAL入力 → 固定容量SPSC → 共通履歴（2秒分、最大FFT長以上） ← 内部デモ信号
                              ├→ トリガー・測定 → ピクセルごとの極値 → Scope GPUバッファ
                              └→ 最新Nサンプル → 窓・FFT・平均 → ピクセルごとの極値 → Spectrum GPUバッファ
                                                                            ↓
                                                        共通WGSLパイプライン + egui
```

FFTは今回UI側で実行します。サイズと更新頻度を制限し、実測結果を確認してから、機能追加で予算を超える場合にワーカーへ移します。GPUに送る線分数はどちらのプロットも画面幅に比例します。FFTのCPU処理はO(N log N)、履歴の読み取りはO(N)です。

## 進める順序

| 段階 | 実装するもの | 完了を判断する条件 |
| --- | --- | --- |
| 1：今回 | Scope＋Spectrum、共通入力、内部デモ、独立したGPU状態 | 既知信号の周波数・振幅・DC/Nyquist補正・平均の数値テスト、二画面のGPU読み戻し、画面確認、CPU計測が成功 |
| 2：時間と周波数の観察 | スペクトログラム、XY/Lissajous、共通の停止・カーソル | スペクトログラムの履歴は固定容量テクスチャ。連続STFTをワーカーで生成し、時間順序と欠落を検証。3画面以上の同時動作を実測 |
| 3：測定器としての基盤 | チャンネルルーティング、入力校正、プリセット、配置の保存 | サンプル番号・サンプルレート・チャンネル・校正・欠落情報を含む共通データモデル。各機能の設定を再現可能 |
| 4：出力と応答測定 | 実オーディオ出力、スイープ、FRF/Bode、THD+N | 入出力のクロック差・ループバック遅延・安全な出力レベルを扱う。測定帯域とノイズの定義を固定して既知系で検証 |
| 5：高度な解析と記録 | ロックイン、インピーダンス、記録、UDP/外部ADC | 基準信号・機器の校正と同期を明示。ディスク・ネットワーク処理が取得やUIを止めない |

画像のような自由配置は段階3で導入します。先に独立した解析状態と更新周期を確立すると、配置を変えても解析や取得に影響が出にくくなります。

## 次に進める作業単位

段階1と **2a：連続STFTの基盤** は実装済みです。段階1の数値テスト・GPU読み戻し・画面確認・CPUベンチマークは [READMEの確認結果](README.md#スペクトル追加版の確認結果2026-10-04) にあります。2aの数値・キュー検証、BlackHole 16chでの確認、変更前後のUIフレーム間隔p95と欠落の記録は [2aの確認結果](README.md#連続stftと16ch基盤の確認結果2026-10-04) にまとめています。GPU実行時間と入力から表示までの遅延は引き続き未計測です。

次の実装単位は **2b：スペクトログラム表示** です。Spectrumの表示は最新窓のスナップショット解析を維持し、別の専用ワーカーが連続STFTを生成します。2bではこの連続結果を時間順序・欠落情報とともに循環テクスチャへつなぎます。以下をそれぞれ独立して検証・レビューできる変更に分けます。

| 作業単位 | 範囲 | 完了を判断する条件 |
| --- | --- | --- |
| 2a：連続STFTの基盤 | 共通入力から固定容量キューを通して専用ワーカーへ渡す。FFT計画・作業メモリを再利用し、窓長とhop間隔を明示する。入力ブロック・解析結果にサンプル番号、サンプルレート、CH、世代番号、欠落情報を持たせる | 入力の分割・履歴の折り返しによらず同じ窓列を生成。既知信号の周波数・振幅、窓の開始位置・順序を数値テスト。キュー飽和、入力変更、停止・再開時に欠落や古い世代を扱え、音声コールバックやUIを待たせない |
| 2b：スペクトログラム表示 | 2aの結果を固定容量の循環テクスチャへ追加。時間・周波数・dBFSの表示範囲と対象CHの設定を追加し、Scope＋Spectrumと同時表示 | 時間軸をサンプル番号とFsから計算。テクスチャの折り返しでも行の順序を保ち、失われた区間を明示。3画面のGPU状態・表示変更が互いに干渉せず、継続動作でメモリが増えない |
| 2c：XY / Lissajous | 共通履歴の同じフレームにあるCH 1／CH 2をXYとして描画。独立した表示範囲・GPU状態と設定の入口を追加 | 同相・逆相・90度位相差の既知信号で直線・円／楕円を確認。欠落の前後を連結しない。モノラル入力の扱いを明示し、他のプロットと同時表示できる |
| 2d：共通の停止・カーソル | 上部の停止操作で全測定器の観察対象を保持。時間カーソルは共通のサンプル座標を使い、周波数カーソルは対応する解析窓と周波数を示す | 停止後にワーカーの遅着結果で表示が変わらず、表示設定は変更可能。再開・入力切り替えで古い世代を除外。各表示のカーソル値が同じ保持データと整合し、停止中に連続再描画や不要なGPU転送を行わない |
| 2e：段階2の統合検証 | 3画面以上の同時表示、通常幅／狭い幅、入力切り替え、停止・再開、連続動作を確認。現在の構成の基準値と比較 | 数値テスト・GPU読み戻し・画面確認に加え、CPU処理時間、UIフレーム時間p95、入力欠落、ワーカーの欠落、メモリ使用量を記録。目標を超えた処理を特定し、段階2の完了条件を確認 |

2aで導入するデータ情報は連続解析に必要な最小限とし、入力校正・任意のチャンネルルーティング・プリセット・自由配置の保存は段階3で扱います。各作業の追加時に対応する設定だけをUIへ出し、数値の正しさ、取得への影響、同時表示の性能を確認してから次へ進みます。

### マルチチャンネルの方針と2aの実装範囲

コアは1〜16chの同期した入力フレームを扱います。CPALのコールバックで最初の2chへ切り詰めず、全chを共通のサンプル番号で取得し、入力ch数に応じた固定容量履歴へ保持します。16chを超える入力は明示的にエラーにし、黙って切り捨てません。デモは現在の2chのままです。

連続STFTは選択した1chを解析します。入力ブロックと結果にFs・入力ch数・対象ch・世代・サンプル位置・欠落情報を付け、キューへのコピーとFFT処理を対象chに限定します。将来、解析対象が増えても全16chのFFTを無条件に実行しない構成です。窓長は1,024〜32,768点、UIから使うhopはN/4。窓関数・DC除去・対象chは現在のSpectrum設定を共有し、STFTの振幅は窓ごとのdBFSで平均・ピーク保持を適用しません。

入力キューは256フレーム×64ブロック、結果は16行の再利用プールです。入力の欠落時は部分窓を捨て、新しい連続区間から窓を生成します。結果が溢れた場合は失った窓数を次の結果へ付けます。停止・入力切り替え・解析設定変更は世代で古い結果を除外します。UIは現時点で結果の最新メタデータだけをPerformanceメニューへ反映し、スペクトログラム画像は2bで追加します。

現在のScopeはCH 1／CH 2の2本表示を維持します。Spectrumとトリガーの対象は取得した全chから選択できます。任意のchを表示トレースやXYの軸へ割り当てるルーティング、全16chの同時解析・表示、校正・保存は後続段階で扱います。BlackHole 16chで全chの信号対応とCH 16の連続解析を検証できるQA手順を用意しています。

## 設定と配置の方針

今回、設定を探すための長いスクロールを減らし、グラフを広く使える構成に変更しました。

| 場所 | 現在の役割 | 拡張時の扱い |
| --- | --- | --- |
| 上部 | 共通の開始／停止、取得状態 | 停止・カーソルなど全測定器に作用する操作を集約。設定のスクロールに影響されない |
| 左側 | 入力、Scope、Spectrum、Workspace & helpのアコーディオン | 一つの設定項目を開き、閉じた項目にも現在値を表示。幅を変更でき、パネル全体を隠せる |
| 各グラフの見出し | CH・測定値・表示スケール、Settingsボタン | Settingsから対象の設定を開き、その位置へスクロール。今後の測定器にも同じ入口を設ける |
| グラフ上部 | 同時／単独表示の切り替え、設定パネルの表示切り替え | 段階2では追加した測定器の表示選択をまとめる。設定を開く操作と表示の有効化を分離する |
| 下部 | サンプルレート・CH・入力形式・欠落数 | 取得状態は常時表示。GPU名やCPU処理時間はPerformanceメニューから確認する |

二画面の配置はAutomatic / Side by side / Stackedを選択できます。Automaticは利用可能な幅に応じて左右／上下を選び、Side by sideでも幅が不足すると上下へ切り替えます。設定項目の開閉で取得やFFTの設定をリセットしません。パネルの表示状態・選択項目・配置指定は現在のセッション内で保持し、起動をまたぐ保存は段階3のプリセット・配置保存で扱います。

段階2でスペクトログラム・XYを追加するときは、各グラフの見出しに日常的な操作だけを置き、窓関数・平均・表示範囲などの詳細は対象の設定へまとめます。測定器が増えて一覧が長くなる段階では、左側を「測定器一覧」と「選択した測定器の設定」に分け、全測定器の詳細を一列に積み重ねません。入力・校正・ルーティングは共通設定として扱います。

段階3の自由配置ではグラフを独立したパネルにし、表示状態・パネル配置・解析設定をそれぞれ保存します。入力の変更は共通基盤へ、表示範囲の変更は対象のグラフだけへ伝えます。段階4以降の実出力・記録は入力の開始／停止とは別の操作と状態表示を設け、解析を観察する操作から誤って開始されない配置にします。未実装の測定器や出力機能は現在のメニューには並べません。

## 性能の目標と計測

- ディスプレイ60 Hz時にUIの1フレームは16.7 ms。解析・表示準備のCPU予算は合計4 ms程度を目安にし、フレーム時間のp95と入力欠落も計測する。これは目標であり保証値ではない。
- FFTのサンプル窓時間はN/Fs。48 kHz・8,192点では170.7 ms、Δfは5.86 Hz。更新を30 Hzにしても窓時間や周波数分解能は短縮されない。
- CPUのFFT、CPUの線分準備、GPUの実行時間、表示更新頻度、入力から表示までの遅延を別々に評価する。現状のベンチマークはCPUのみ。
- 新しい解析は音声コールバックに入れない。コールバックでは変換と固定容量キューへの書き込みに限定する。
- 連続STFTや記録を追加する際は解析ごとの固定容量キューと世代番号を導入する。表示は最新結果を使い、履歴・記録では失われた区間を明示する。
- 機能追加後も、停止中の連続再描画を避け、変更のないプロットへの波形転送を省略する。

## 現在の測定上の範囲

振幅はデジタルFSです。スペクトルは片側のビン振幅を窓のcoherent gainで補正し、1 FS peakのビン中心正弦波を0 dBFSと定義します。PSD（dBFS/Hz）、dBm、電圧の測定ではありません。RBWは窓の等価雑音帯域で、独立した可変帯域フィルターや3 dB帯域ではありません。平均は線形電力の指数平均で、指定回数のバッチ平均ではありません。ピーク表示は最も大きいビンであり、サブビン補間は行いません。

今回のFFTは最新窓のスナップショット解析です。処理間隔のすべての窓を網羅しないため、短い過渡現象の検出を保証しません。連続性が必要なスペクトログラム・記録は、段階2以降の専用処理で対応します。
