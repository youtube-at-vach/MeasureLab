## 現在の実行構造と残る境界

```text
CPAL callback → 固定容量SPSC → 測定ワーカー ← Software Loopback／QAデモ
                                ├→ 共通f64履歴・Scopeトリガー・生サンプル統計
                                ├→ 選択CH転送 → Spectrumワーカー
                                ├→ 同期2ch転送 → Lock-inワーカー
                                └→ 固定容量転送 → STFTワーカー
各ワーカー → 世代・整数区間・条件付き結果 → UI表示／保持／非同期ファイルI/O
```

入力・解析の欠落と表示更新の省略を区別する。UI停止・非表示で解析・平均を止めず、Stopは有限の入力終端を処理してから保持する。遅着・旧世代の結果を混ぜない。Scope捕捉区間とSpectrum窓を同時刻と誤認させず、不足区間をゼロ埋めして取得済みにしない。

SpectrumのContinuousはN/4の全窓、Live／Latestは最新窓の観察で、後者は過渡捕捉を保証しない。48 kHz・512kの完全窓は約10.92秒。更新頻度・Δf・RBW・窓時間・平均の整定を区別し、f64の基準経路を維持する。

### 4：Software LoopbackとLock-inによる品質評価

基本波の同期2ch Lock-inは実装済み。REFの強度・正弦波適合を確認し、同じ整数区間で位相補正してからサンプル時計による二段複素EMAへ渡す。X/Y・Rはpeak、正の位相は応答の進み。欠落・REF喪失では平均を破棄して再整定する。定義と許容差は [Lock-in検証](validation/LOCKIN_2026-10.md) を正本にする。

4aの結果再利用では、Lock-inのf64値・REF診断・完全窓数・整数区間・取得時の設定と校正をJSON／CSVへ保持し、保存・参照読み込みで状態と数値定義の整合を検証する。比較画面は取得条件を併記し、整定済みで公称Fs・CH・REF／フィルター設定・両CHの校正が一致する場合だけ差を表示する。仮想系の確認条件は [結果再利用の検証](validation/LOCKIN_RESULTS_2026-10.md) に分ける。4bではBlackHoleの保存・再起動・再測定と、通常幅／狭幅の保持・参照比較画像を確認した。Software LoopbackのSingle・未充填状態の再撮影は未受信で未完了。実機と段階4全体の完了判定も残す。

外部仮想I/Oの条件と失敗は [BlackHole Lock-inの検証](validation/BLACKHOLE_LOCKIN_2026-10.md) に分ける。2ch／16chの4つのFsで振幅・位相・極性・微小応答・REF回復・整定応答・キュー飽和後の回復、同一ワーカーでのFs／デバイス変更が通過した。2ch・48 kHzのGUIなし600秒は正常区間の入力／Lock-in欠落0、誤差・RSS安定を確認した。CoreAudioの接続時通知は明示的な起動待ち区間へ分け、測定中の入力失敗を無視しない。実際の入力コールバックは512フレーム固定であり、可変長の外部I/O確認にはしない。高Fsの通常GUI起動と外部Singleは接続通知との境界を4cへ残す。

物理ループは [UAC-232 Lock-inの検証](validation/UAC232_LOCKIN_2026-10.md) に分ける。macOSの44.1／48／96／192 kHz、ユーザーのL→L／R→R接続で、R／位相を同じ入力窓の独立計算とPSD換算へ照合し、既知の振幅比・位相変更、REF喪失／不安定からの再整定、CH交換／自己検査、ステップ応答、有限Stop・JSON／CSV・再取得比較、意図的な入力キュー飽和後の回復を条件付きで確認した。48 kHzのGUIなし600秒は正常区間の入力／Lock-in欠落0、位相変動幅0.00248°、RSS変動4 KiBで通過した。入力コールバックは固定512フレームで、可変長の確認にはしない。−40 dB応答では高レベル時から約0.11〜0.16°の位相変化を観測し、実入力との演算一致とアナログ経路のレベル依存位相を区別する。原因と物理校正精度を未確認として残し、段階4全体を完了にしない。

**段階3から引き継ぐ回帰条件：**

* 1／2chと16ch・CH 16、48／96 kHzを主条件にし、44.1／192 kHzも供給可能な経路で境界確認する。8k／512k、3窓、f64／選択可能なf32、振幅／PSD、DC除去、平均・保持を照合する。計算可能なFsと実機が対応するFsは区別する。
* 同一入力・整数区間で表示幅・倍率・配置・非表示化を変えても、f64値・平均窓数・保持条件が変わらない。Scopeの周期信号・単発パルス・DC・無信号・雑音・欠落、Normal待機・Single再待機・Autoset成立／不成立を維持する。
* 外部仮想I/O・利用可能な物理入力で、調整→捕捉→設定・結果保存→再起動→停止中復元・参照読み込み→再測定→比較を行い、CH・Fs・単位・校正版・区間・解析条件・欠落を照合する。
* 通常幅1440×860・狭幅1040×780と高DPIで、単独／2表示／4表示、Spectrogram／XY／Lock-inを確認する。プロット内の主要数値・カーソルと面積を維持し、未取得・整定・トリガー待機・停止待ち・失敗を正常値と区別する。文字の強調・SI書式の改善は後続とする。
* release・VSync条件で600秒と複数hopを含むUI停止を評価する。正常条件の取得／解析入力欠落0、GUIなしとの予定窓・平均・保持の一致、初期充填後のRSS安定を確認する。意図的飽和では欠落位置・数・無効化・回復を照合する。
* UI間隔p95は約16.7 ms、フレームCPUは約4 msを目安とする。解析総時間p95はContinuousでhopの25%以下、512k Latestの100 ms観察で25 ms以下を初期目標とし、最大時間・キュー高水位・入力消費の最長停止も記録する。
* 操作要求受付→状態表示の反復p95 100 ms以下を目標とする。完全窓の取得、整定、ファイルI/O、Stopの解析待ちは別計測。CPU総負荷、GPU実行時間、窓終端→解析→表示の遅延も独立して測り、p95の差や合計で代用しない。

機器がない層は未確認として残す。プロトタイプの公開は可能でも、未実施を段階4の実機合格に置き換えない。

### 5：同期2chの比較測定

最初の用途は、同じ入力時計の2chに対するゲイン・位相・遅延の比較とする。

* 同じ整数区間・窓の複素クロススペクトル、各CHの自己スペクトル、平均とコヒーレンスを定義する。位相・遅延の符号、ゼロ入力、相関のない雑音、欠落・CH変更時の無効化を先に決める。
* 共有演算は入力世代・時計・区間・CH・窓・精度・校正・解析条件が一致する範囲だけに限定する。汎用計算グラフを先行実装しない。
* 既知のゲイン・位相・整数／分数遅延・雑音・フィルターで理論値と照合する。CH間の振幅・位相校正が未確認なら、その制限を数値・保存結果に残す。
* 表示だけでなく、停止・条件付き保存・読み戻し・再測定まで完成させる。Scope／Spectrum／Lock-inと1〜16ch基盤を回帰確認する。

### 6：実出力と最小の応答測定フロー

まずGeneratorの明示的な開始・停止・レベル制限・切断処理を実装し、その後に2ch REF／応答による最小FRF／Bode用途を作る。

* 出力は取得・UIから独立した容量固定の経路にする。設定復元だけで出力を開始しない。入力と出力のデバイス・時計差・遅延・欠落を識別する。
* 信号生成→仮想DUT→共通入力→解析の経路を先に検証し、外部ループバック・物理系で既知ゲインとフィルター応答を照合する。
* 測定フローは開始・停止・完了・失敗と条件付き結果を持つ。励振、解析帯域、整定、校正、保存・再実行までを完了条件とする。
* THD／THD+N・IRや複数の測定器は同時に追加せず、最小FRFが成立してから個別に計画化する。
