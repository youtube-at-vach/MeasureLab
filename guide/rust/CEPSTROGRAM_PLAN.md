# Cepstrogram の実装計画

状態は**初期実装と内部基本受け入れ済み**。Spectrogram内の解析モードとして、ケプストラムの演算・数値結果を独立させている。代表48 kHz・選択1chの全窓長／Overlapで両モードのLive・反復操作を比較した。後続の実装者は [現在の方針](../CURRENT_DIRECTION.md) → [Rust PLAN](PLAN.md) → 本書の順に読み、着手時のコードと差分を確認する。

本書は実装の契約と追加受け入れの範囲を保持する。設定形式は版11で、版1〜10を読み込む。数値・状態・許容差・合否は実装とテストを正本とする。既存のGenerator／同期2ch比較の評価や配布候補の受け入れを置き換えず、初回Rust公開の必須条件にも追加しない。

## 1. 採用する構成

**UIはSpectrogramの解析モード、DSPと結果型は独立したCepstrogram**とする。初期版で独立した計器IDや入力経路は増やさない。

| 項目 | 初期版の決定 |
| --- | --- |
| 配置 | 既存のMonitor／Spectrogramの枠を使う |
| 選択 | Analysisに`Spectrogram / Cepstrogram`を置く。既定はSpectrogram |
| 演算 | f64の実ケプストラムを計算・保持する |
| 描画 | 実ケプストラムからPower cepstrogramを表示する |
| 入力 | 既存の1〜16chから選択1ch。CH・窓長・窓・DC除去・Overlapを両モードで共用 |
| 実行 | 既存STFTワーカー内で選択中のモードを処理。Cepstrogramのときだけ追加演算 |
| 履歴 | 選択中の解析結果だけを保持。モード間の履歴変換・同時保持は行わない |
| 表示設定 | 周波数用とケフレンシー用の軸・色設定を別に保持。時間幅は共用 |
| 保存 | 測定設定と表示設定の保存・復元に対応。測定結果のJSON／CSV／PNG出力は対象外 |

共有対象は窓のスケジューリング、サンプル時刻、欠落管理、有界転送・履歴、スクロールと描画の枠である。周波数とケフレンシー、スペクトル電力とケプストラム係数は型・単位・読出しAPIで区別する。汎用計算グラフや全計器の再構成は行わない。

現行コンソールは同じ計器IDを重複配置しないため、モード切替だけでは両者の同時表示はできない。同時比較、別CH・別窓での並行解析、専用の断面表示や結果保存が必要になった段階で、独立したMonitor計器への昇格を検討する。その際にも本計画のDSPと数値定義を再利用する。

## 2. 用途と初期範囲

倍音の間隔に由来する周期性や、直接音と反射が重なった信号の遅延間隔が時間とともにどう変わるかを観察する。自動的なピッチ・反射経路の判定は行わない。振幅スペクトルだけでは信号全体の単純な時間移動を識別できないため、同期2ch比較の遅延測定の代わりにはしない。

初期版に含めるのは連続解析、Live／Hold、過去の閲覧、時間A／B、ケフレンシーの読値、欠落・無効状態、設定保存・復元である。複素ケプストラム、MFCC、CPP／CPPS、リフタリング、プリエンファシス、リサンプリング、平均・ピーク保持、周波数帯域を限定した解析、独立したCepstrum断面計器は対象外とする。Praat互換は保証しない。

## 3. 数値契約

### 3.1 入力と前処理

* 窓長は既存の`STFT_SIZES`の1,024〜32,768点、窓は周期Rectangular／Hann／Blackman-Harris、Overlapは50／75／87.5%を使う。初期設定・既存設定の共通値を引き継ぎ、モード選択だけで窓長を変更しない。
* Remove DCは既存と同じく窓掛け前の算術平均を引く。共通設定として明示し、Cepstrogramで暗黙の前処理を追加しない。
* Cepstrogramでは前段FFT・対数・逆FFTをすべてf64で実行する。Spectrogramの保存済みf32選択は保持し、戻ったときに再使用する。要求設定と実際に適用した精度を分ける。
* 入力は未校正FSを基準とし、Scope／Spectrumの校正を暗黙に適用しない。時間・ケフレンシーは取得時の公称Fsを使う。
* 不完全な窓、存在しないCH、欠落を含む窓をゼロ埋めして解析しない。前段は現行のSTFTと同じ完全窓・世代の契約を維持する。

### 3.2 保存スペクトルからの変換

窓を`w`、窓利得を`W = Σw`、前処理後の信号を`x`、正規化前のDFTを`X = DFT(x × w)`とする。本機能では、窓利得で正規化した両側相当の振幅`A = |X| / W`を対数の基準に採用する。

現行のSTFTが保持する片側の振幅二乗`P`からは、次のように復元する。片側化の倍率を戻すことと、負周波数側を対称に構成することの両方が必要である。

```text
s[k] = 1                         k = 0, N/2
       2                         それ以外の片側ビン
P[k] = (s[k] × |X[k]| / W)²
a[k] = ln(A[k] / 1 FS)
     = 0.5 × ln(P[k] / 1 FS²) − ln(s[k])
```

`P=0`はこの段階では`a=−∞`とし、次節の対数下限を適用する。平方根や再二乗を経由せず、f64の対数領域で扱う。描画用dBFS・表示下限・f32・画素縮約値から数値を復元しない。PSDや平均済みSpectrumからも計算しない。

窓利得の正規化は本機能の定義であり、ここでは戻さない。同じ相対下限を使った正規化前の`X`の実ケプストラムとは、0番目の係数だけが`−ln(W)`異なる。独立参照式でもこの基準を一致させる。

### 3.3 対数下限と実ケプストラム

対数下限は各窓の最大振幅に対する相対値とし、表示の色下限とは別の解析設定にする。初期値は`log_floor_db = −160`、設定可能範囲は整数dBで`−300〜−60`とする。これは初期実装の設計値であり、精度保証やノイズ除去の閾値ではない。既存の`Config`／`RowInfo`の等値比較を維持できるよう、解析設定では整数値として保持する。

```text
a_max = max(a[k])                 片側全ビン、DC・Nyquistを含む
l_min = a_max + log_floor_db × ln(10) / 20
L[k]  = max(a[k], l_min)          k = 0 ... N/2
L[N−k] = L[k]                    k = 1 ... N/2−1
c[q] = Re(IFFT_N(L))[q]          逆変換は1/N正規化
τ[q] = q / Fs                    秒
```

DC／Nyquistは鏡映で重複させない。全ビンが0なら`a_max`を使った演算へ進まず、`NoSignal`にする。非有限値や負の`P`は下限へ丸めず、窓全体を`NonFinite`として扱う。下限で置き換えた片側ビン数を結果に保持し、設定値とともに詳細欄で確認できるようにする。値が下限に達すること自体は欠落ではない。

実ケプストラムは偶対称なので、数値履歴は`q = 0 ... N/2`の符号付きf64を保持する。負値は正常値であり、無効値として除外しない。0番目も保持するが、初期版のプロットとAuto色範囲には含めない。単なる入力ゲインの変更では、表現可能な範囲で0番目以外が変わらないことを確認する。

逆FFTは導入済みのRustFFTを使う。最初はN点の複素逆FFTで正しい結果を作り、専用の実逆FFT・SIMD・GPU演算への最適化は実測の必要性から判断する。FFT計画・scratch・出力バッファは解析設定の適用時に解析ワーカーで用意し、窓ごとに作り直さない。

### 3.4 表示量と状態

色は対数パワーから求めるPower cepstrumの規約に合わせ、次で定義する。

```text
Cpower[q] = (2 × c[q])²
Lc[q] = 10 × log10(Cpower[q] / 1)
      = 20 × (log10(abs(c[q])) + log10(2))    c[q] != 0
Lc[q] = −∞                                  c[q] == 0
```

`Cpower`は無次元であり、音響パワーやFS²ではない。カラーバーは`Cepstral power (dB re 1)`とし、dBFS・PSDの単位を流用しない。保存の正本は`c`とし、符号を捨てた`Cpower`だけを保存しない。表示では上の対数式により二乗時のアンダーフローを避ける。

| 状態 | 表示と数値読出し |
| --- | --- |
| Valid | f64の`c`と`Lc`を読める。`c=0`の表示は色の最下端で、値0は有効 |
| NoSignal | 前処理後の全スペクトルが0。中立色の行と理由を示し、係数・Autoの対象にしない |
| NonFinite | 無効な入力・前段・派生演算。無効表示と理由を示し、係数・Autoの対象にしない |
| Missing | 取得・解析・転送・保存の欠落。サンプル位置に欠落表示を残す |
| Waiting／未取得／保持範囲外 | 値を出さず、未取得・範囲外を示す |

状態を数値の0だけで表現しない。`NoSignal`、欠落、未取得を区別する。弱いが非ゼロの入力を自動的に無音と見なす閾値や、ノイズの中から周期性を保証する判定は追加しない。

## 4. ワーカー・履歴・容量

```text
共通取得／測定ワーカー → 選択CH・有界転送 → 既存STFTワーカー
  └ 完全窓 → 既存f64 FFT・片側振幅二乗
       ├ Spectrogram: 振幅二乗を公開（既存のf32 FFT選択も維持）
       └ Cepstrogram: 専用DSPで補正・対数・逆FFT → 符号付きcを公開
  → 共通の有界結果プール → 履歴収集ワーカー → 不変の数値フレーム
  → 表示準備ワーカー → GPU描画
```

* `src/cepstrum.rs`などGUI非依存の専用モジュールを設ける。Spectrumの平均・校正・描画の中へケプストラムを埋め込まない。追加演算を取得コールバック、測定ワーカー、履歴収集、UIに移さない。
* 解析種別と専用条件を`Config`／結果へ持たせる。結果には入力世代、解析世代、実適用したCH・Fs・N・hop・窓・DC除去・精度、アルゴリズム識別子、対数下限、整数窓区間、状態・欠落・下限適用数を保持する。
* 行／フレームの数値は、`SpectrumPower`と`RealCepstrum`など識別できる型に分ける。実装の名前は任意だが、ケプストラムを既存の`power()`／`amplitude()`／`Result::from_stft`へ渡せないAPIにする。解析種別とpayloadの不一致も拒否する。
* 1フレームの有効配列長はどちらも`N/2+1`とし、現在の結果プールと履歴の容量管理を共用する。Cepstrogramの元スペクトルは演算用scratchにとどめ、履歴へ二重保存しない。
* 選択モードの解析は計器非表示・UI受信停止・Hold中も継続する。表示の省略と解析・転送・保存の欠落を別に報告する。飽和時は取得を待たせず、解析できなかった区間を明示する。
* 数値履歴・Hold・選択行・旧新世代・FFT scratch・結果プール・ラスタを合算して有界性を確認する。参照中の過去フレームは値を書き換えない。

現行の履歴上限・フレーム総量・ラスタ・CPU総量は [history.rs](../../src/spectrogram/history.rs)、[viewport.rs](../../src/spectrogram/viewport.rs)、[容量テスト](../../tests/spectrogram_capacity.rs) が正本である。追加scratchも含めて既存の上限内に収めることを先に試み、上限を自動的に倍増しない。変更が必要なら根拠と容量テストを同じ変更に含める。

## 5. 表示・操作・状態遷移

### 5.1 モードと表示の対応

計器ID・配置・ウィジェットIDは固定し、表示中の実結果に応じてタイトルを`Spectrogram`／`Cepstrogram`にする。計器一覧の入口はSpectrogramを維持し、名称・用途検索でCepstrogramにも到達できるようにする。検索・計器選択だけで解析モードや入出力を変更しない。

停止中の編集に備え、次回Start用の要求モードと保持データの実適用モードを別に持つ。タイトル、単位、軸、カーソル、表示設定の編集対象は保持データ側に合わせ、解析欄に次回適用の選択を示す。保持フレームがない場合は現在の解析世代に適用済みの条件で空の表示を作り、まだ解析を開始していない場合は要求条件を使う。実行中のモード切替直後は新モードの完全窓待ちを示す。

| 操作・状態 | 必要な挙動 |
| --- | --- |
| 入力実行中のモード・共通解析条件・有効な対数下限の変更 | 解析世代を更新し、旧履歴・Hold・選択行・この履歴由来の時間A／B・ケフレンシーカーソル・表示キャッシュを解除。新しい完全窓を待つ |
| 停止中の解析条件変更 | 保持結果・その軸と読値は維持。次回Startに適用し、過去の行を再解析しない |
| Stop処理中の編集 | 次回Start用に予約。停止対象の世代・終端・保持結果を書き換えない |
| Hold／Live・時間幅・パン・ズーム・色の変更 | 解析世代や数値を変えない。LiveはHoldと履歴由来の時間選択を解除 |
| 入力停止 | 現行STFTの保持と遅着結果除外の契約を維持。末尾未解析分を補完しない |
| 入力再開・入力元変更 | 旧入力の数値・カーソル・表示要求を無効化し、新世代の完全窓を待つ |

Spectrogram中に非アクティブなCepstrogram専用設定を復元・編集しても、現在のSTFTをリセットしない。前モードの遅着結果・ラスタ・保留クリックが次モードへ入らないよう、要求と応答のキーに解析種別・世代・表示条件を含める。

### 5.2 軸・色・縮約

* 縦軸は現行どおり経過時間、新しい行を上に置く。行の占有区間はhop、実際の解析窓はN点であり、両者を別に保持する。
* 横軸は初期版では線形の`Quefrency (ms)`のみ。内部単位は秒で、格子間隔は`1/Fs`、表示可能範囲は`1/Fs〜N/(2Fs)`。0番目をプロットへ入れない。
* ケフレンシーの要求範囲の初期値は0〜0.020秒とし、表示時に上記の有効範囲へ制限する。最低2点を表示できる範囲を確保する。Fs・N変更で保存した要求値を勝手に上書きせず、実表示範囲を示す。NaN、無限大、負の下限、下限が上限以上の範囲は拒否する。
* ケフレンシーを指すズーム・パン・範囲リセットを用意する。周波数用の`Fs/N`、Nyquist、Hzフィールドへ秒を詰める実装は禁止する。軸の原点・刻み・上限・変換を明示して描画枠を共有する。
* 初期色設定はViridis・Auto ON、Auto未確定時のManual範囲は−80〜0 dB re 1とする。Spectrogram側の配色・範囲・Autoを変更せず、両モードで独立保存する。
* Autoは表示中の有効な`q>=1`の`Lc`だけを対象にする。既存のパーセンタイル・余白・平滑化の方針を共有できるが、`c<0`を無効にしたり、`c`へ直接対数を取ったりしない。有効点不足時は同一モード・世代の最後の有効範囲、なければそのモードのManual設定を使う。Manual設定を持たない旧設定には初期範囲を補う。
* 画素縮約は`abs(c)`または同値の`Lc`の最大値を保持する。符号付き`c`の最大値では負のピークを失う。時間縮約でも同じ規則を使い、欠落・無効区間を有効ピークで覆い隠さない。

例えば48 kHz・4,096点では窓約85.3 ms、75% Overlapの行間隔約21.3 ms、正側のケフレンシー上限約42.7 msとなる。格子間隔は測定精度ではなく、窓長・雑音・対数下限・入力時計も結果に影響する。既存のLive表示待ち時間を再利用し、追加演算後の応答性は別に測る。

### 5.3 カーソルと他計器

時間A／Bは実フレームと整数サンプル区間を保持し、Scope／XYとの時刻連動を維持する。共通の生履歴が既に失われた場合は、他計器の値を補完しない。カーソル・ホバーの数値は表示画素ではなく元のf64フレームから読む。

ケフレンシーカーソルA／Bは秒単位の専用状態として持ち、最寄りの有効な`q`、ms、符号付き`c`、`Lc`、A／Bのケフレンシー差を表示する。周波数カーソルや`nearest_bin(hz, ...)`を流用しない。Cepstrogram上の操作でSpectrumの周波数を移動しない。`1/τ`をピッチの確定値として表示する機能は初期版に含めない。

既存のClear cursorsは新しいケフレンシー選択も解除する。モード適用時はこの履歴に属する時間選択・ケフレンシー選択を解除し、Scope由来の時間選択やSpectrumの周波数選択を不要に消さない。

Cepstrogramの実適用中は履歴Spectrumへの連動入口を無効化し、理由を表示する。モード適用時に既存の履歴連動を解き、Spectrumを通常の結果へ戻す。Spectrumを普通の計器として隣へ配置することは可能とし、`Split view with… / Spectrum`など配置と連動が一体の経路も誤接続しない。UIだけでなく結果変換側でも種別を検査する。停止中の予約変更だけでは、保持中のSpectrogramとその正当な連動を壊さない。

## 6. 設定保存・互換性・多言語

測定設定には要求モードと整数`log_floor_db`を追加する。CH・共通FFT設定・Overlapは引き続き共用する。Cepstrogramのf64固定は実適用条件へ反映し、Spectrogramに戻すための精度選択は保持する。アルゴリズムの識別子は数値結果・QA条件に持たせ、定義を将来変更したときに区別できるようにする。

WorkspaceにはCepstrogram専用のケフレンシー範囲、Manual色範囲、配色、Autoを追加する。保持行・カーソル・Autoの一時結果・次回Startを待つ実データは保存しない。表示する数値結果の条件と、保存する次回Start用の条件を混同しない。

設定形式は版11。版1〜10の読込ではSpectrogramを既定とし、既存の軸・色・精度・Overlap・配置を保持する。新項目には定義した初期値を入れる。未知のモード、不正な範囲・対数下限・型・未来版は検査して拒否し、失敗時に現行設定を部分更新しない。復元だけで入力・出力・解析を開始しない。

英語キー・英語文言・呼出箇所だけを変更し、既存の`spectrogram`グループ内にCepstrogram用のキーを追加する。計器一覧など共通部分は必要な英語キーだけを変更する。他言語・`i18n/source-hashes.json`は変更しない。[I18N](I18N.md) に従い、実装PR前に`check --base <基準SHA>`で範囲を確認する。

### 8.1 数値検証

条件・許容差・合否はテストコードを正本にする。次の意味を持つケースを追加し、実装自身の変換関数を期待値生成に使わない。

* 小さいNの直接DFT／逆DFTによる参照を作り、全ビンの窓利得・片側倍率・対称化・1/N・0番目・符号を照合する。実運用Nと全窓・Overlapにも別の回帰を用意する。
* 既知の間隔と係数を持つ二つのインパルスで、エコー位置、正負のケプストラム係数を確認する。Rectangular・DC除去OFFなど解析的な期待値が成立する条件と、窓による変化を分ける。
* 倍音を含む周期信号とその周期変化で時間追跡を確認する。単独正弦波だけを周期性の受け入れにしない。雑音を加えた条件は周期検出を保証せず、参照式との一致と表示を確認する。
* 入力ゲイン変更時の0番目の変化と他係数の不変性、正負の入力ゲイン、対数下限の感度・適用数、微小な正の値・0を確認する。
* 無音、DC除去後の定数、平坦なスペクトル、非有限入力を区別する。平坦な非ゼロスペクトルの`q>0`がほぼ0であることと、NoSignalを混同しない。
* 異なるFs・Nでケフレンシーの刻み・正側上限と時刻を確認する。長いサンプル番号は整数差を先に取る。実ケプストラムの対称性と循環表現の範囲外を、物理的な遅延保証へ広げない。

### 8.2 実行・表示・互換性の検証

* 不規則な入力ブロック、入力・結果・履歴の飽和、非有限窓からの回復、UI受信停止、非表示、Hold中の解析継続を確認する。既存の1〜16chの割当・欠落管理を維持する。
* 実行中・停止中・Stop処理中に両方向のモード変更、共通条件変更、対数下限変更、入力再開を繰り返し、旧フレーム・ラスタ・クリック・カーソルが混在しないことを確認する。
* 正負で絶対値の等しい係数が同じ色になること、負のピークが縮約後にも残ること、0番目・無音・欠落がAutoを支配しないことをCPU参照とGPU読み戻しで確認する。
* 時間A／BとケフレンシーA／B、ホバー、ズーム・パン、Clear、保持範囲外、通常幅／狭幅、停止中の予約表示を確認する。Spectrumの周波数カーソルを誤って変更しない。
* 履歴Spectrumへの全入口を監査する。通常Spectrogramの時間A／B連動・数値・校正制限・出力制御は従来のまま、Cepstrogramでは型検査とUIの両方で連動を拒否する。
* 旧設定の既定モード、両モードの往復、独立した軸・色・Spectrogramのf32設定保持、壊れた設定・未来版の拒否、起動時OFFを確認する。通常のScope／Spectrum結果出力へCepstrogramを混入させない。

### 8.3 負荷と既存回帰

まず選択1ch・代表48 kHzで、全窓長・OverlapとLive／Hold／表示操作を確認する。高Fs・入力16ch・小さい窓と高Overlap・CPU競合は追加の限界条件とする。同じ入力・ソースSHA・ビルド・表示条件で両モードを比較し、STFT処理時間、追加逆FFT時間、取得・解析・結果・保存の欠落、表示応答のp95と最大、メモリ、有限Stopの進捗を測る。

既存のSpectrogramモードでは追加逆FFT・追加数値履歴が動かないことを確認し、既存ベンチ・容量・数値・履歴Spectrum・GUI回帰を維持する。新旧モードの容量交換と終了時の解放を [容量テスト](../../tests/spectrogram_capacity.rs) へ加える。既知の高負荷時の欠落・表示停止を既存問題として記録しつつ、新機能の成功や解決済みと扱わない。性能合否の条件は対応するQAコードに置き、文書に独立した許容差表を作らない。

実時間性能の測定に最適化済み実行ファイルが必要な段階だけ、理由を明示してreleaseを使う。C1〜C3の通常開発は`dev-fast`と通常テストで進める。内部演算・Software Loopback・仮想I/O・物理経路の確認範囲を区別し、USB抜去試験は実施・計画しない。接続変更は入出力停止・ストリーム解放後に限る。
