# Rust GUI の開発・翻訳手順

[現在の方針](../CURRENT_DIRECTION.md) と [PLAN](PLAN.md) に従い、機能開発と翻訳を独立したPRにする。I1の検査・差分・レビュー用出力、I2の共通API・言語設定・英語フォールバック・フォントと、I3の共通画面・7計器の英語キー化を実装している。`View → Language`で既存9言語の識別子を選択・保存できる。英語基準の全9言語・全10グループの初回翻訳を完了した。以後の追加・変更は1言語・1グループの独立タスクで抽出する。確認済み訳の改訂は下記の視覚レビュー手順を使う。I5の基盤受け入れと翻訳手順の整備は完了した。未翻訳・未確認・古い訳は英語へ戻る。翻訳本文の網羅と基盤の受け入れを別に扱う。

## 通常の機能開発

必要な`en-US`の文言・安定キー・呼出箇所だけを変更する。他言語の翻訳・一括同期・英語コピーによる穴埋めを行わない。英語の文言変更・変数変更・削除は後続の翻訳差分へ渡し、未翻訳を理由に機能PRを止めない。

```bash
./.venv/bin/python -m pip install -r requirements-i18n.txt
./.venv/bin/python scripts/i18n.py check --base origin/main
./.venv/bin/python -m unittest discover -s scripts -p 'test_i18n.py'
```

`check`はYAMLの構文・型・重複・名前空間、英語呼出キーと変数、翻訳元メタデータを検査する。`--base`を付けると、そのコミットから作業ツリーまでの未追跡ファイルを含む変更範囲も検査し、他言語・翻訳元メタデータの変更を拒否する。I1での空のメタデータ登録だけは初期化として許容する。ローカルで`--base`を省略した場合は構造・整合性だけを検査し、PR範囲を検証済みとはしない。

他言語の欠落・空値・翻訳元未確認・英語変更による古い訳・削除済み英語の旧訳は、キーごとの警告にする。古い訳の変数差分も再翻訳対象として警告する。現行英語を確認済みとする訳の変数不一致、更新した訳の不整合、構文・重複の問題はエラーにする。英語と同じ`FFT`や単位・記号という理由では未翻訳と判定しない。

CIは`locales/`・`i18n/`・検査スクリプト・Rustソースの変更を分類し、必須`docs-lint`内で構造・差分の回帰テストと検査を行う。YAMLだけのPRでも検査とRustのコンパイル・回帰検証を省略しない。PRはbase SHA、main Pushは直前SHAとの変更範囲を検査する。手動CIは構造検査と警告出力を行う。CIも通常開発コマンドも、翻訳生成・自動修正を実行しない。

## カタログと呼出規約

正本は`locales/<group>/<locale>.yml`、言語別形式の`_version: 1`を使う。グループは`common`／`shell`／`io`／`oscilloscope`／`spectrum`／`spectrogram`／`xy`／`generator`／`lockin`／`comparison`。ウィジェットごとには分けない。

```yaml
_version: 1
io:
  start_input: Start input
  selected_device: "Input device: %{name}"
```

本文には名前空間を明示する。ネスト形式と`io.start_input`のようなドット形式は同じ最終キーへ正規化される。ファイルのディレクトリ名はキーへ自動付加しない。原則として同名グループへまとめるが、ファイル間移動でキーと英語本文を維持した場合は再翻訳にしない。同じlocale内の全ファイルを横断して重複と、`io.device`／`io.device.name`のような値と名前空間の衝突を拒否する。別localeの同じキーは正常である。

キーは意味を表す小文字英数字とアンダースコアのセグメントをドットでつなぐ。本文は文字列だけとし、数値やYAMLの真偽値に見える文字列は引用する。変数は`%{name}`形式の名前付き変数にする。文章を断片連結せず、表示文言からキーを生成しない。

GUI共通APIの呼出契約は次の形を使う。検査はこの形のリテラルキー・名前付き引数を認識する。関数の別名import・動的キー・動的な引数一覧は拒否する。列挙型は [表示名の対応](../../src/app/text.rs) のGUI側のmatchで、各候補を静的な呼出へ対応付ける。コアの名前・enum値を翻訳しない。数値と単位の記号・地域別書式も維持する。

```rust
i18n::text("io.start_input");
i18n::format("io.selected_device", &[("name", device_name)]);
```

localeは`en-US`／`ja`／`fr`／`de`／`es`／`pt`／`ru`／`zh`／`ko`。英語を基準にし、旧`en`や旧GUIのキー・未実装機能の訳を一括移植しない。製品の他言語カタログはI4の独立タスクで作る。検査スクリプトの翻訳例は一時ディレクトリ、実行時APIの最小QAカタログは`tests/fixtures/i18n/`に隔離する。

## GUI共通APIと表示設定

`src/i18n.rs`に`rust-i18n`の初期化・埋め込み読込・変数展開を閉じ込める。依存は`desktop`だけで有効にし、コールバックや測定・解析・GeneratorワーカーからlocaleやAPIを参照しない。検査は共通API以外の`rust_i18n`参照と、GUI境界以外の`i18n`参照を拒否する。外部エラー詳細、数値の地域別書式、JSON・CSV・ログの識別子は翻訳しない。

固定文言の`i18n::text`は`&'static str`を返す。カタログはlocaleごとに英語フォールバックを解決して保持し、毎フレームの文字列確保と二重検索を避ける。動的文言の`i18n::format`は`&[(&'static str, &str)]`を受け取り`Arc<str>`を返すため、eguiへは`.as_ref()`で渡す。GUIスレッド上で、定義済みキーごとの直近の引数・結果だけを保持する。同じ引数なら結果を再利用し、引数が交互に変わる場合は再生成する。値別の無制限キャッシュは持たない。保存・復元・書き出し・Autosetの通知は [表示用の状態](../../src/app/status_text.rs) に引数を残して表示時に解決し、保持中の通知も言語変更へ追従させる。低層の外部エラー詳細は原文を保つ。

`i18n::initialize`は`measurelab.locale`をeframeの利用者設定から復元する。初回・未知・廃止識別子は`en-US`へ戻す。`set_locale`は表示キャッシュを破棄し、フォントを更新して再描画を要求する。測定設定・保存結果とは独立し、取得・出力を開始しない。eguiのIDには固定のsaltを使い、翻訳した表示名を保存・操作対象の識別に用いない。

非英語の文言は、英語本文・翻訳元ハッシュ・翻訳本文ハッシュ・変数がすべて一致する場合だけ表示する。欠落・空値・未確認・古い訳は英語へ戻す。メタデータの読込失敗も英語フォールバックにする。QA用の訳やメタデータを製品のカタログへ混入しない。

フォントは [Noto Sans CJKとライセンス](../../assets/fonts/README.md) を同梱し、eguiの既定フォントの後ろに補完として追加する。日本語・韓国語・中国語の字形をlocaleで選び、比例・等幅の両ファミリーでCJK・キリル文字・アクセント・単位を検査する。Helpから著作権とライセンスを確認できる。全localeの解決済みカタログ全文字を比例・等幅で検査する。測定中・保持中の切り替え、通常幅・狭幅・倍率・模擬native scale、英語とのウォームフレームCPU比較は [I5のQA](VALIDATION.md#多言語基盤i5) を使う。現在のIntel Macの手動操作・実モニター間DPIは既存方針どおり対象外である。

## 独立した翻訳タスク（標準手順）

翻訳は毎回 **1言語・1グループ** にする。推論量の少ないモデルにも、下記の定型指示と訳文欄だけを渡せる。YAML編集・ハッシュ計算・削除キーの判定を翻訳担当へ要求しない。訳語の意味・自然さの確認は残す。

1. 最新mainから翻訳ブランチを作り、作業ツリーがクリーンな状態で準備する。`ja`と`io`は依頼された対象へ置き換える。

   ```bash
   ./.venv/bin/python scripts/translate.py prepare --locale ja --group io
   ```

2. `dist/i18n/answers.json`の各`text`だけを対象言語の訳に置き換える。`null`は保留。`key`・`english`・行・locale・基準SHAを編集しない。既存訳・旧英語・変数は、読取専用の`i18n/translation-task.json`で確認できる。
3. 適用・検査し、`git diff`で訳語と変更範囲をレビューする。

   ```bash
   ./.venv/bin/python scripts/translate.py apply
   ./.venv/bin/python scripts/translate.py verify
   git diff --stat
   git diff -- locales i18n
   ```

4. [共通検証](../../.agents/workflows/tool_usage.md)を行い、対象YAML・`i18n/source-hashes.json`・`i18n/translation-task.json`をコミットする。`dist/`はコミットしない。コミット後も`verify`を実行できる。PRには対象言語・グループ・タスクの基準SHA、完了／保留範囲、検証結果を書く。

`prepare`は差分JSONと訳文欄を生成する。`apply`は全回答をメモリ上で検査してから、対象YAMLとメタデータへ反映する。英語本文・UTF-8 SHA-256と変数、重複・対象外キー・基準SHA、機能コードとの混在を検査し、英語から削除済みの対象キーは訳とメタデータから除く。既存の確認済みキーは対象へ含めない。専門語・単位が英語と同じでも、確認して`text`を埋めればよい。

この書き戻しは翻訳タスクで明示的に呼ぶ専用操作であり、通常開発・CIから呼ばない。`scripts/i18n.py check`／`diff`／`export-csv`は引き続き読取専用。CSVからの逆インポートは行わない。

失敗時はエラーで示すキーの`text`を修正して再適用する。YAML・メタデータ・タスクJSONを直接修正して検査を通さない。準備後にHEAD・英語・機能コード・カタログを変更した場合は適用を拒否する。回答を作業ツリー外へ保管し、変更を解決してクリーンな最新HEADで準備し直す。`apply`済みのカタログも上書きしない。適用後に訳を改訂する場合は、適用差分を保管して準備時点へ戻すか、別の明示的な翻訳レビュータスクにする。

### 確認済み訳文の視覚レビュー

初回翻訳後の改訂は、スクリーンショットと呼出箇所から問題のキーを特定し、1言語・1グループの明示的なレビュータスクにする。`prepare`に繰り返し指定できる`--review-key`で、現行英語と整合する既存訳だけを抽出する。通常の未翻訳差分と混ぜず、対象外のキー・言語・機能コードは変更しない。

```bash
./.venv/bin/python scripts/translate.py prepare --locale ja --group common \
    --review-key common.place_cursor
```

以後は通常と同じく回答JSONの`text`だけを編集し、`apply`→`verify`を実行する。既存訳はタスクJSONで確認でき、`null`の行は既存訳を維持する。ツールが訳文ハッシュを計算するため、YAMLやハッシュを手で編集しない。同じ問題を他言語へ横断確認する場合も、改訂が必要な言語・グループごとに抽出・適用・検査を分ける。

GUI QAは`--locale`で選んだ言語の画像を保存できる。画像の読み取りやすさ・訳語の適切さは画像を読んで判定し、自動assertionだけで合格にしない。

```bash
caffeinate -du ./.venv/bin/python scripts/qa_gui_redesign.py \
    --binary target/dev-fast/measurelab --locale ja \
    --case scope-wide --case scope-compact --output dist/i18n-visual-review/ja
```

### 翻訳モデルへの定型指示

```text
対象: <依頼された言語>、<依頼されたグループ>。
dist/i18n/answers.json の text だけを、同じ行の english から翻訳してください。
key、english、locale、base_revision、行の追加・削除は禁止です。
%{name} 形式の変数、FS/Fs、CH/REF/SIG/GEN/OUT、単位・数式は保持してください。
入力停止と出力停止、取得と保持、未校正と校正済みを区別してください。
既存訳と文脈は i18n/translation-task.json を読んで確認できます。
意味を確定できない行は null のまま保留し、理由を報告してください。
YAML、翻訳元ハッシュ、英語カタログ、Rustコードは編集しないでください。
```

### 管理者向けの検査入口

低水準の差分抽出も残す。`diff --base HEAD --locale <言語> --group <グループ>`は未翻訳・未確認・古い訳と削除を抽出する。`check --base <基準SHA> --task i18n/translation-task.json`はタスクをbaseから再計算し、抽出後の改変・対象外キー・機能実装の混在を拒否する。`translate.py verify`は保存済みタスクの基準SHAを使う同等の範囲検査である。

メタデータは`i18n/source-hashes.json`の`version: 1`と`translations[locale][key]`に、確認した`source`、その`source_hash`、訳文の`translation_hash`を保持する。ハッシュは改行を含む文字列のUTF-8 SHA-256で、Unicodeを自動正規化しない。英語変更の機能PRでは更新せず、翻訳PRだけで更新する。YAMLが正本で、回答JSONは作業用、タスクJSONはレビュー対象として保持する。

## レビュー用CSV

```bash
./.venv/bin/python scripts/i18n.py export-csv > /tmp/measurelab-i18n-review.csv
```

キー順にグループ・英語・各言語と`missing`／`unreviewed`／`stale`／`current`／`removed`の状態を出力する。引用符・カンマ・改行はCSVとしてエスケープする。CSVは必要時だけ生成するレビュー成果物で、YAMLが正本である。CSVからの逆インポートは実装しない。
