# Rust GUI の開発・翻訳手順

[現在の方針](../CURRENT_DIRECTION.md) と [PLAN](PLAN.md) に従い、機能開発と翻訳を独立したPRにする。I1の検査・差分・レビュー用出力、I2の共通API・言語設定・英語フォールバック・フォントと、I3の共通画面・7計器の英語キー化を実装している。`View → Language`で既存9言語の識別子を選択・保存できるが、製品の他言語翻訳はまだ行っていないため、表示は英語のままである。

## 通常の機能開発

必要な`en-US`の文言・安定キー・呼出箇所だけを変更する。他言語の翻訳・一括同期・英語コピーによる穴埋めを行わない。英語の文言変更・変数変更・削除は後続の翻訳差分へ渡し、未翻訳を理由に機能PRを止めない。

```bash
./.venv/bin/python -m pip install -r requirements-i18n.txt
./.venv/bin/python scripts/i18n.py check --base origin/main
./.venv/bin/python -m unittest discover -s scripts -p 'test_i18n.py'
```

`check`はYAMLの構文・型・重複・名前空間、英語呼出キーと変数、翻訳元メタデータを検査する。`--base`を付けると、そのコミットから作業ツリーまでの未追跡ファイルを含む変更範囲も検査し、他言語・翻訳元メタデータの変更を拒否する。I1での空のメタデータ登録だけは初期化として許容する。ローカルで`--base`を省略した場合は構造・整合性だけを検査し、PR範囲を検証済みとはしない。

他言語の欠落・空値・翻訳元未確認・英語変更による古い訳・削除済み英語の旧訳は、キーごとの警告にする。古い訳の変数差分も再翻訳対象として警告する。現行英語を確認済みとする訳の変数不一致、更新した訳の不整合、構文・重複の問題はエラーにする。英語と同じ`FFT`や単位・記号という理由では未翻訳と判定しない。

CIは`locales/`・`i18n/`・検査スクリプト・Rustソースの変更を分類し、必須`docs-lint`内で構造・差分の回帰テストと検査を行う。YAMLだけのPRでも検査とRustのコンパイル・回帰検証を省略しない。PRはbase SHA、main Pushは直前SHAとの変更範囲を検査する。手動CIは構造検査と警告出力を行う。CIも通常開発コマンドも、翻訳生成・自動修正を実行しない。

## カタログと呼出規約

正本は`locales/<group>/<locale>.yml`、言語別形式の`_version: 1`を使う。グループは`common`／`shell`／`io`／`oscilloscope`／`spectrum`／`spectrogram`／`xy`／`generator`／`lockin`／`comparison`。ウィジェットごとには分けない。

```yaml
_version: 1
io:
  start_input: Start input
  selected_device: "Input device: %{name}"
```

本文には名前空間を明示する。ネスト形式と`io.start_input`のようなドット形式は同じ最終キーへ正規化される。ファイルのディレクトリ名はキーへ自動付加しない。原則として同名グループへまとめるが、ファイル間移動でキーと英語本文を維持した場合は再翻訳にしない。同じlocale内の全ファイルを横断して重複と、`io.device`／`io.device.name`のような値と名前空間の衝突を拒否する。別localeの同じキーは正常である。

キーは意味を表す小文字英数字とアンダースコアのセグメントをドットでつなぐ。本文は文字列だけとし、数値やYAMLの真偽値に見える文字列は引用する。変数は`%{name}`形式の名前付き変数にする。文章を断片連結せず、表示文言からキーを生成しない。

GUI共通APIの呼出契約は次の形を使う。検査はこの形のリテラルキー・名前付き引数を認識する。関数の別名import・動的キー・動的な引数一覧は拒否する。列挙型は [表示名の対応](../../src/app/text.rs) のGUI側のmatchで、各候補を静的な呼出へ対応付ける。コアの名前・enum値を翻訳しない。数値と単位の記号・地域別書式も維持する。

```rust
i18n::text("io.start_input");
i18n::format("io.selected_device", &[("name", device_name)]);
```

localeは`en-US`／`ja`／`fr`／`de`／`es`／`pt`／`ru`／`zh`／`ko`。英語を基準にし、旧`en`や旧GUIのキー・未実装機能の訳を一括移植しない。製品の他言語カタログはI4の独立タスクで作る。検査スクリプトの翻訳例は一時ディレクトリ、実行時APIの最小QAカタログは`tests/fixtures/i18n/`に隔離する。

## GUI共通APIと表示設定

`src/i18n.rs`に`rust-i18n`の初期化・埋め込み読込・変数展開を閉じ込める。依存は`desktop`だけで有効にし、コールバックや測定・解析・GeneratorワーカーからlocaleやAPIを参照しない。検査は共通API以外の`rust_i18n`参照と、GUI境界以外の`i18n`参照を拒否する。外部エラー詳細、数値の地域別書式、JSON・CSV・ログの識別子は翻訳しない。

固定文言の`i18n::text`は`&'static str`を返す。カタログはlocaleごとに英語フォールバックを解決して保持し、毎フレームの文字列確保と二重検索を避ける。動的文言の`i18n::format`は`&[(&'static str, &str)]`を受け取り`Arc<str>`を返すため、eguiへは`.as_ref()`で渡す。GUIスレッド上で、定義済みキーごとの直近の引数・結果だけを保持する。同じ引数なら結果を再利用し、引数が交互に変わる場合は再生成する。値別の無制限キャッシュは持たない。保存・復元・書き出し・Autosetの通知は [表示用の状態](../../src/app/status_text.rs) に引数を残して表示時に解決し、保持中の通知も言語変更へ追従させる。低層の外部エラー詳細は原文を保つ。

`i18n::initialize`は`measurelab.locale`をeframeの利用者設定から復元する。初回・未知・廃止識別子は`en-US`へ戻す。`set_locale`は表示キャッシュを破棄し、フォントを更新して再描画を要求する。測定設定・保存結果とは独立し、取得・出力を開始しない。eguiのIDには固定のsaltを使い、翻訳した表示名を保存・操作対象の識別に用いない。

非英語の文言は、英語本文・翻訳元ハッシュ・翻訳本文ハッシュ・変数がすべて一致する場合だけ表示する。欠落・空値・未確認・古い訳は英語へ戻す。メタデータの読込失敗も英語フォールバックにする。QA用の訳やメタデータを製品のカタログへ混入しない。

フォントは [Noto Sans CJKとライセンス](../../assets/fonts/README.md) を同梱し、eguiの既定フォントの後ろに補完として追加する。日本語・韓国語・中国語の字形をlocaleで選び、比例・等幅の両ファミリーでCJK・キリル文字・アクセント・単位を検査する。Helpから著作権とライセンスを確認できる。通常ビルドの他環境の手動確認・各言語の長文・測定中の切り替えとUI負荷の受け入れはI3以降のI5に残る。

## 独立した翻訳タスク

対象言語・グループの英語が固まった後、新しい翻訳用ブランチを現在のmainから作る。言語とグループを選び、**編集前のクリーンなHEAD**から差分を抽出する。次は日本語・共通入出力を対象にする例であり、全言語へ展開する指示ではない。

```bash
./.venv/bin/python scripts/i18n.py diff --base HEAD --locale ja --group io > i18n/translation-task.json
```

JSONには基準コミット・言語・グループ・対象キー・旧／新英語・必要な変数・現行訳・現在の英語ハッシュ・既訳の翻訳元ハッシュを含む。追加・文言変更・変数変更・削除を区別する。初回は欠けたキー、後続では翻訳元未確認・古い訳も対象にし、削除は整理対象に分ける。`--base <過去SHA>`で英語の履歴比較もできるが、その出力を別のbaseの翻訳PRに流用しない。

AIへは対象差分だけを渡し、既存訳は用語の参考にする。変更は対象localeのYAMLと対象キーのメタデータに限定する。無関係なキーや他言語、機能コード、英語カタログを変更しない。抽出JSONは編集しない。翻訳PRには`i18n/translation-task.json`も含める。機能PRではこのファイルを更新しない。前の翻訳PRからファイルが残っていても、変更していなければ通常の機能PRとして検査する。

メタデータの正本は、`rust-i18n`の読込範囲外の`i18n/source-hashes.json`とする。

```json
{
  "version": 1,
  "translations": {
    "ja": {
      "io.start_input": {
        "source": "Start input",
        "source_hash": "英語文字列のUTF-8バイト列のSHA-256（小文字hex）",
        "translation_hash": "翻訳文字列のUTF-8バイト列のSHA-256（小文字hex）"
      }
    }
  }
}
```

上記のハッシュ表記は説明用で、そのまま登録できない。`source`は確認した英語本文を保持し、`source_hash`と`translation_hash`はそれぞれの文字列をUTF-8でSHA-256にする。改行も文字列の一部で、Unicodeの自動正規化は行わない。ハッシュ計算は検査スクリプトと同じ`hashlib.sha256(text.encode("utf-8")).hexdigest()`を使う。英語が変わった機能PRではメタデータを更新せず、翻訳PRで意味・変数を確認したキーだけを更新する。再確認後の訳が同じ専門語ならメタデータだけの更新も可能である。

```bash
./.venv/bin/python scripts/i18n.py check --base <抽出時の基準SHA> --task i18n/translation-task.json
```

検査は保存したJSONをbaseのカタログ・メタデータから再計算し、許可キー・英語ハッシュ・変数・現行訳・基準リビジョンの一致を確認する。対象外の編集、英語変更後の古いJSON、翻訳とメタデータの不一致、機能実装との混在を拒否する。適用前に失敗したらカタログを上書きせず、最新baseから抽出し直して差分を確認する。JSONやCSVからYAMLへ書き戻す機能はない。

部分翻訳も可能で、残りの未翻訳・要確認キーを警告とPR本文で明示する。英語から削除済みのキーを整理するときは、訳とメタデータを両方削除する。英語が現存するキーの訳削除を翻訳完了とは扱わない。

## レビュー用CSV

```bash
./.venv/bin/python scripts/i18n.py export-csv > /tmp/measurelab-i18n-review.csv
```

キー順にグループ・英語・各言語と`missing`／`unreviewed`／`stale`／`current`／`removed`の状態を出力する。引用符・カンマ・改行はCSVとしてエスケープする。CSVは必要時だけ生成するレビュー成果物で、YAMLが正本である。CSVからの逆インポートは実装しない。
