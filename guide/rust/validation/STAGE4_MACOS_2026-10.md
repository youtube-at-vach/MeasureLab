# 段階4のmacOS統合評価

対象：2026-10-12、`60021e3f`上の作業差分。macOS 14.8.9、x86_64、Rust／Cargo 1.99、CPAL 0.18.2、Metal／AMD Radeon R9 M290X。別OSの実機検証は今回実施せず、後続タスクへ送る。測定は公称Fs・未校正FSで、実時計や物理校正の精度保証ではない。

段階4は今回のmacOS条件で受け入れ完了とする。通常GUIの長時間確認は中断までの約270秒をユーザーが十分として受け入れ、600秒の再実行は行わない。途中終了の観測と、有限Stop・最終照合まで完走した試験を分ける。

## 境界と評価方法

BlackHole 2ch／16chとUAC-232を列挙できた。物理QAのL出力→L入力、R出力→R入力はユーザーが接続維持を確認した。UAC-232への生成は最大0.1 FS peak・DCなしで、終了時に入出力を解放し、公称Fsを戻す。

大きなFFTのQA出力は接続要求から0.5秒だけを起動待ちにし、通知時刻・区間・件数を記録する。以後の出力通知とすべての入力失敗・欠落を失敗にする。再接続の起動待ちで過去の測定中の出力失敗を消さないことを境界テストで確認する。通常ビルドの入力失敗判定を緩めない。

物理Lock-inは同じ整数窓の独立DC／sin／cos最小二乗へ照合し、Rは相対0.2%＋2 µFS、位相0.05°を基準にする。再取得の差はR 1%＋2 µFS・位相0.1°。外部SingleはAutoで入力が安定した後に待機させ、480サンプルの生入力を独立適合して基準へ照合する。τ=1秒のLock-inは整定途中の暫定値を持ち得るため、状態Settlingと512k未充填を確認する。接続直後の短いSingleをこの成功へ含めない。

UAC-232の定常値はR約0.058887 FS peak、位相約0.004°。30秒の有限結果と独立計算との差はR −0.2992 µFS、位相−0.0006268°。実測値は未校正の機器・接続・音量に依存し、0.1 FS出力とADCの入力FSが同じ物理レンジとは仮定しない。

## 512kと負荷の確認

修正前のBlackHole 16ch・96 kHz・512k Continuous・4表示の30秒試験は、入力欠落0・20窓を取得したが、区間を分けていない出力通知の判定で失敗した。起動境界を計測した再試験では、出力通知3件は開始後0.065〜0.287秒、0.5秒以降0件で、振幅0.125 FS peak・20予定窓・入力／解析欠落0を照合した。

| 実測 | BlackHole 16ch・96 kHz・30秒 | UAC-232・48 kHz・30秒 |
| --- | --- | --- |
| UI間隔p95 | 17.800 ms | 17.330 ms |
| フレームCPU p95 | 2.240 ms | 2.170 ms |
| FFT p95／最大 | 17.500／23.026 ms | 15.000／14.911 ms |
| Spectrumキュー高水位 | 4／256 | 10／256 |
| 入力利用可能→解析完了p95 | 18.400 ms | 17.250 ms |
| 解析完了→UI提出p95 | 17.100 ms | 623.526 ms |
| 入力利用可能→UI提出p95 | 33.470 ms | 639.363 ms |

同じ整数窓の結果群で各区間と全区間を直接集計する。p95の差・合計は使わない。ヒストグラムの上側丸めによりFFT p95が最大より僅かに大きくなる場合がある。UAC-232の提出遅延とUI最大8,222 msには意図的UI停止を含み、停止なしの通常遅延とは扱わない。CPU上の時刻であり、ADC・GPU実行完了・scanoutは未計測。

反復Spectrum単体ベンチマークは各条件200回で、512kのf64 p95 10.724 ms／最大11.374 ms、f32 p95 8.916 ms／最大9.757 ms。25 msの初期目安を下回った。単体値をI/O付きの値へ置き換えない。

UAC-232・48 kHz・4表示・512k Continuousの長時間試験は、約270秒で12,935,680入力フレーム、95 FFT窓、捕捉欠落0まで進んだ。RSS記録は275秒まであり、60秒以降168,564〜169,796 KiB、CPU使用率中央値21.6%。バックグラウンドで別作業が行われていたため、専有条件の性能値とは扱わない。中断時には入力underrun／overrun通知2件が記録され、最終有限結果・出力通知監査・UI分布の完了記録がない。中断時の通知原因は未確認で、ユーザーが約270秒を受け入れたことをもって600秒成功や終了時の正常性を保証しない。

最終ソースのrelease版で30秒の物理profileを再実行し、有限Stopの入力失敗なし、捕捉／Spectrum／Lock-in／STFT入力欠落0、独立数値照合、JSON保存、入力停止、出力解放後の通知監査まで通過した。取得1,512,448フレーム・予定8 FFT窓、出力通知は起動待ち3件・測定中0件、STFT表示行の省略65件。完了記録を含む終了コード0を確認した。これを中断した約270秒の最終照合へ置き換えない。

## 失敗とクラッシュの照合

BlackHole 16chの通常GUI結果再利用では、最初の取得後の再接続で入力underrun／overrunにより失敗した。通常の入力失敗は検知・伝播されており、成功へ変更しない。最終releaseの18ケースGUIマトリクスでは、Software Loopback／BlackHole 2ch／16chの通常幅・狭幅・保存再起動比較、9つのLock-in表示・状態、安定入力からのBlackHole 2ch／16ch Single、GPU読み戻しがすべて通過した。先の再接続失敗は残し、全起動の安定性を保証しない。

物理Singleの接続直後の短い捕捉は、整定済みの基準との独立生入力比較に失敗した。安定したAuto入力からのSingleへ条件を分ける。この条件変更は接続直後の成功保証ではない。

2026-10-12 16:25:31のmacOSクラッシュ記録は`measurelab-qa-final`のSIGABRTで、QAログの`single.lockin.result.x.is_none()`の失敗と一致した。Autoから待機したSingleでは、既に処理した完全Lock-in窓の暫定値をSettlingとして保持する。値なしというQA側の期待が誤りだったため、外部SingleではSettling・有限480サンプル・512k未充填・独立数値照合を確認し、内部Software Singleだけ値なしを確認するよう修正した。測定アルゴリズムを変えて期待値へ合わせない。修正後のdebug再試験に加え、終了監査を補強したrelease版で同じ保存・再取得・外部Single・終了を5回繰り返した。5回とも独立数値照合・設定復元・画像保存・正常終了まで通過し、新しいmacOSクラッシュ記録はなかった。この反復条件で再発0であり、全状況の無事故保証ではない。

撮影前の数値照合が成功してもGPU読み戻しが届かず終了する症状も再現した。失敗時は`IODisplayWrangler`のDevicePowerState／CurrentPowerStateが0、UserIsActiveが0で、表示がスリープしていた。`caffeinate -u`で状態4へ戻すと、同じdebug QA・通常幅・比較表示で画像保存まで通った。オフスクリーンGPU読み戻しも通過した。QAはフォーカスと撮影を分離し、非ブロッキングpollと最大4回の再要求を10秒以内に行い、実際の画像保存を必須にする。通常の描画・測定へ待機を追加しない。
