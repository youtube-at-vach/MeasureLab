# BlackHoleによる外部I/O Lock-inの検証

対象：2026-10-12、`a837b04c`上の作業差分（`codex/lockin-blackhole-validation`）。macOS 14.8.9、x86_64、Rust／Cargo 1.99、CPAL 0.18.2。BlackHole 2ch／16chを対象にする。物理ADC／DAC・物理REF／応答・独立した入出力時計の検証ではない。

## 経路と基準

QA専用出力の既知f32信号をBlackHoleへ流し、通常のCPAL入力コールバック→固定容量SPSC→共通f64測定ワーカー→独立Lock-inワーカーを通す。内部Software Loopbackや生成位相をREFの代用にしない。REFはCH 1、応答は2chではCH 2、16chではCH 16。通常アプリのGenerator・物理出力を追加した確認ではない。

基準は750 Hz、REF 0.125 FS peak、応答gain 0.5・進み30°・3サンプル相当の遅れ・DC 0.2 FS。R=0.0625 FS peak、Gain=0.5、位相は`30° − 360° × 750 Hz × 3 / Fs`。各CHは同じBlackHole時計で取得する。絶対入出力遅延や実時計精度の測定にはしない。

| 公称Fs | 理論位相 |
| --- | --- |
| 44.1 kHz | 11.632653061° |
| 48 kHz | 13.125° |
| 96 kHz | 21.5625° |
| 192 kHz | 25.78125° |

通常は積分窓4,096、τ=0.02秒、Tracking有効。厳密な定常値比較は30τ以上で行う。X/Y/R誤差<1e-7 FS peak、位相誤差<1e-4°、REF周波数誤差<1e-3 Hzを許容差にする。BlackHoleのf32量子化を含む許容差であり、物理入力の精度保証ではない。

接続ごとの0.5秒は起動待ちとして入出力通知を別記録する。最初の0.3秒を容量固定の入力キューへ保持し、入力通知の有無とキュー欠落0を確認してから測定ワーカーへ渡す。さらに0.2秒後、平均をリセットして測定区間を始める。サンプル・連番を捨てたり変更したりしない。その後に出力エラー、入力失敗、正常条件の入力／Lock-in欠落があれば失敗にする。意図的飽和では0.75秒コールバックの取得を継続したまま入力キューを消費せず、回復区間を別に確認する。

## 確認項目

* 基準振幅・位相・遅れと極性反転を理論値へ照合。CHの入れ替えでは逆位相・Gain=2、同じCHの自己検査では位相0°・Gain=1を確認する。
* 微小応答1.25e-8 FS peakは応答DCなしでX/Y/R誤差<1e-13 FS peak。基準のDC付き応答と分け、微小ACと強いDCが同時にある場合のf32動的範囲保証にはしない。
* REF 1003 Hz、ヒント1000 Hzの追従を照合。REFをDCのみ／強い二次高調波へ変更すると数値と平均を破棄し、正弦波へ戻すとSettlingを経て回復する。
* τ=0.1秒の振幅ステップを観測し、隣接3窓のX/Yが独立した二段フィルターの消去式`y[k] = 2β y[k−1] − β² y[k−2] + (1−β)² target`に誤差<1e-7で従うことを確認する。`β=exp(−N/(Fs×τ))`。192 kHzでは30 Hzの結果通知より窓を長くするため、この観測だけ積分窓16,384を使う。他の条件では4,096を使う。
* 有限Stopの最新完全窓・平均寄与区間・窓数・入力終端を照合。停止中の次回用編集と反復Stopで保持値を変えない。JSON／CSVの条件付き保存・読み戻し・入力再開後の参照比較を行う。
* 実入力キュー飽和ではMissingと数値破棄を確認し、capture・共通測定・Lock-inの欠落数を一致させる。回復した平均の区間を過去の区間へ混ぜない。

## 実測結果

BlackHole 2ch／16chの44.1／48／96／192 kHz、計8条件で一連の確認が通過した。各条件の定常評価は3秒で、正常測定区間の入出力エラー・入力／Lock-in欠落は0。入力コールバックは全条件で512フレーム固定だった。48／96／192 kHzでは8,192点の同じpeak定義のSpectrum振幅とも誤差<1e-7 FSで一致した。44.1 kHzは非ビン中心のため、このFFT比較を合格項目に含めない。

| Fs | 2ch／16chの最大R誤差（FS peak） | 最大位相誤差 | 意図的キュー欠落（2ch／16ch） |
| --- | --- | --- | --- |
| 44.1 kHz | 8.354e-10 | 9.408e-12° | 11,230／11,742 |
| 48 kHz | 1.405e-9 | 8.630e-7° | 12,352／12,352 |
| 96 kHz | 7.078e-11 | 7.092e-7° | 25,216／25,728 |
| 192 kHz | 2.738e-10 | 6.012e-8° | 50,432／52,992 |

意図的な欠落数はcallback連番とアプリの容量固定キューに対する値である。CoreAudioの起動通知からバックエンド内部の失われたサンプル数を逆算した値ではない。復帰後の完全窓から新しい平均を作り、capture・共通測定・Lock-inの欠落数が一致した。

2ch・48 kHzの600秒安定性が通過した。GUIなしのrelease、caffeinateあり、ビルド・他の音声試験の並行実行なし。17,079回の結果観測で最大R誤差1.405e-9 FS peak、最大位相誤差8.630e-7°、正常区間の入出力エラー・入力／Lock-in欠落0。整定区間を含むフィルターリセット以降の完全窓は7,039、有限入力終端は29,480,448で、寄与区間・最新完全窓・部分窓を照合した。

プロセス開始30〜617秒の575件のRSSは最小／最大とも46,440 KiB（45.35 MiB）。同区間587秒の累積CPU時間差は43.44秒（1論理CPU換算約7.4%）。GPU・GUIの負荷やフレーム時間ではない。600秒の16ch・他のFs、通常表示、512kの性能評価へこの結果を代用しない。

同じ測定ワーカーで、2ch・48→96 kHz→16ch・96 kHz→2ch・44.1 kHz→16ch・192 kHz→2ch・48 kHzの6条件を順に開始・停止し、世代10〜15、CH・Fs・理論位相・入力／Lock-in欠落0を照合した。16chから2chへ変更してCH 16を残した場合はUnavailableで数値を破棄し、CH 2へ修正すると新しい区間から再整定した。BlackHoleの公称Fsは2ch・48 kHz、16ch・96 kHzへ復元した。

## アプリの結果再利用とGUI

2ch／16chとも48 kHz、通常幅1440×860で、設定・JSON／CSV／PNG保存、停止中の次回用CH／Fs／校正／τ編集、保持値・取得条件の不変性、設定復元・参照読み込み・再測定・条件付き比較が通過した。別プロセス・狭幅1040×780でも同じデバイスの保存条件から再測定し、X/Y/R差<1e-8 FS peak、位相差<1e-4°、Gain差<1e-7を満たした。

4条件の画面を2倍の物理解像度で撮影し、Scope／Lock-inの保持表示と参照比較のCH・公称Fs・単位・REF診断・整数区間を視覚確認した。Metal／AMD Radeon R9 M290X、VSync、caffeinateあり。比較内容は縦スクロールする。PNGの結果書き出しはScope／Spectrumで、Lock-inの数値・条件はJSON／CSVへ保持する。

BlackHoleの短いSingleを含む初回GUI QAは出力通知またはトリガー待ちのタイムアウトで失敗した。この試行を外部Single合格にしない。外部I/Oの結果再利用QAは整定済みの保持結果で終了し、Singleの起動通知との境界は4cへ残す。Software Loopbackの480サンプルSingle・未充填512k／Lock-inの数値回帰は通過したが、その画面の撮影は今回も未受信で失敗した。BlackHoleの成功画像でSoftware Loopbackの未撮影状態を埋めない。

## 失敗と確認範囲

初回は接続通知を測定区間と分離しておらず、出力エラーで失敗した。16ch・96 kHzは起動中の入力通知で2試行が失敗した。入力単独では96 kHz・191,488フレーム・欠落0、既存16ch既知信号QAでは起動中の入力通知を別記録した後に192,000フレーム・欠落0で通過した。新しいQAもワーカーへ渡す前に入力の起動待ちを設けた。通常アプリの入力エラーを無視する変更は行っていない。接続通知を測定成功へ読み替えず、区間を再取得して判定する。

192 kHz・4,096窓の初回ステップ観測は30 Hzの通知で隣接窓を受け取れず失敗した。これは連続した観測窓の不足であり、その試行をステップ応答合格にしない。16,384窓へ変えた観測を再実行し、通過した。

物理REF／応答、物理CH間の遅延・極性・位相、実時計校正、物理校正精度、異なる入出力時計、Windows／Linux実機は未確認。可変コールバック長は固定512フレームだけの観測のため未確認。高Fsの通常GUI起動で接続通知から回復できるかも未確認であり、QAの起動待ちを通常アプリの動作保証にしない。GUI表示を含む600秒負荷、512k、外部Single、操作応答・GPU実行時間の評価は4cへ残す。Lock-inと段階4の実用完了には物理系の検証が必要である。
