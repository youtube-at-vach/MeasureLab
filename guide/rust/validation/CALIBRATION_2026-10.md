# Scope数値校正の検証

検証日：2026-10-08。対象は`8ef050118`を基点とする`codex/scope-calibration`の作業ツリー。段階3dの最初の単位として、CHごとの校正定義とScope数値読み出しを確認した。Spectrum校正、設定保存・復元、結果書き出し、物理基準の精度はこの範囲に含めない。

## 定義と環境

各CHの校正は `y = gain × x(FS) + offset`。ゲインは有限・非ゼロで負値も許容し、オフセットは有限、物理単位と参照条件は必須とする。ID・非ゼロの版・係数・単位・参照条件を不変の定義として保持する。同一セット内で同じID・版へ異なる定義を割り当てる要求は拒否する。未校正CHの数値はFS。

対象はScopeのRMS・Peak・P-Pと実サンプルカーソル。生履歴・波形座標・トリガー・FFT入力はFSを保持する。各取得サンプルをf64で換算してから統計を計算し、RMSはオフセットを含む。有限値の二乗がオーバーフローする条件ではスケール付きの二乗和を使う。換算値やP-Pが非有限なら数値結果を無効とし、別サンプルやゼロで代用しない。

macOS 14.8.9（23J631）、x86_64、Rust/Cargo 1.99、Metal / Intel Iris Pro Graphics 6200。数値テストはGUIなしでも実行した。画面・ライフサイクルQAは`qa`付きdevビルド、GPU読み戻しは通常のreleaseビルド。内部デモと合成入力を使い、物理デバイスの校正係数を得た試験ではない。

## 数値・入力ワーカー

* CH 16の生サンプル`[-0.5, 0, 欠落, 0.5] FS`へゲイン−2 V/FS、オフセット1 Vを適用。換算値`[2, 1, 欠落, 0] V`からRMS = √(5/3) V、Peak = 2 V、P-P = 2 V、取得数3を照合した。RMSの絶対許容差は1e−15 V。履歴周回、CHの入れ替え、未校正CH、欠落だけの区間、存在しないCHも確認した。
* 1,024点・整数周期の0.25 FS peak正弦波へ4 V/FS、オフセット2 Vを適用。RMS = √4.5 V、Peak = 3 V、P-P = 2 Vを絶対許容差1e−14 Vで照合した。DC入力のオフセットもRMSへ含める。1 ± 1e−9 FSのP-Pはf64で保持し、誤差2e−16 FS未満を確認した。
* ゲイン0・NaN・∞、非有限オフセット、版0、空や過長・制御文字付きのメタデータ、FS／dBFSを校正単位とする要求、範囲外CH、変更した同一IDの同版を拒否した。既存の定義は変更されない。
* 1e200のゲインで二乗がオーバーフローする有限RMSを確認。換算値自体やP-Pがオーバーフローする場合は`NonFinite`、欠落・範囲外CHは`Unavailable`として区別した。
* 16chの取得キューからCH 16／CH 8の正弦波を測定ワーカーへ渡した。CH 16の4 V/FS・オフセット0.5 VでRMS = √0.75 V、Peak = 1.5 V、P-P = 2 Vを照合し、生RMS・FFT電力・履歴はFSのまま保持した。校正が入力CHへ対応する入れ替え、Stop後の2,048点への観察幅変更、次回用の新版への変更、再開後の新版適用、16ch→2chでCH 16が利用不可になる境界を確認した。受信済みの旧結果は校正版1を維持し、新しい入力世代の結果は版2を保持する。

## GPU・UI

`--gpu-smoke`は成功。Scope・Spectrum・Spectrogram・XYの読み戻し、保持時の転送省略、Spectrogramの折り返し・欠落・最大FFTのNyquistを確認した。

`MEASURELAB_UI_SMOKE_ROUTING=1`と`MEASURELAB_UI_SMOKE_CALIBRATION=1`を使い、通常幅／狭幅で校正パネルとScopeを撮影・確認した。CH 16は0.375 FS peakの正弦波に4 V/FS・オフセット0.5 Vを適用し、RMS約1.173 V・P-P 3.000 Vを表示する。未校正のCH 8はRMS約0.177 FS・P-P 0.500 FS。A/Bカーソルも対応する単位を表示し、点の描画位置と波形軸・トリガーレベルはFSを維持する。設定パネルには取得結果の校正と次回用の校正を区別して表示する。画像は`dist/calibration-qa/`へ保存した。

内部デモのライフサイクルQA（計測5秒＋起動待ち2秒）は成功。停止中に校正を設定しても保持中の統計・カーソル値と校正版が変わらず、再開時に適用されること、入力ソース変更で次回用の校正と旧読み出しを解除することを確認した。非表示・再表示、遅着結果の除外、各測定器の保持・設定変更・世代更新の既存確認も維持した。取得／STFT入力／STFT結果の欠落は0。

このQAは操作変更を含むdevビルドで、通常の性能基準値とは比較しない。eframe処理p95は5.550 msで、CPU 4 msの目安を満たしたとは扱わない。
