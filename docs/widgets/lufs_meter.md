# LUFS Meter (ラウドネスメーター)

![Lufs Meter](../assets/widgets/lufs_meter.png)

## 概要

LUFS Meterは、放送や配信サービス（YouTube, Spotify, Netflixなど）で標準的に使用される「ラウドネス（人が感じる音の大きさ）」を測定するメーターです。国際規格 ITU-R BS.1770-4 に準拠したアルゴリズムを使用しています。同時に通常のピークメーターやRMSメーターも表示します。

## 共通機能

このウィジェットは Detachable Wrapper の共通機能に対応しています。詳細は [Detachable Wrapper](detachable_wrapper.md) の説明書を参照してください。

## 主な指標の意味

### LUFS

ラウドネス（音量感）の単位です。

* **Momentary (M)**: 瞬間的なラウドネス（400msの窓）。レベルの激しい変動を確認するのに使います。
* **Short-term (S)**: 短期間のラウドネス（3秒の窓）。直近の音量感を把握するのに適しています。
* **Integrated (I)**: 測定開始から現在までの全体の平均ラウドネス。番組や楽曲全体の音量を評価する最も重要な指標です。無音区間などを除外するゲート処理が行われます。

### その他の指標

* **RMS**: 信号の実効値（電気的な平均レベル）。
* **True Peak (TP)**: 連続した4倍FIR補間でサンプル間ピークを推定します。実機DACやスピーカーの出力を測定するものではありません。
* **Peak (Pk)**: デジタルデータ上の最大サンプル値。
* **Crest Factor (CF)**: True PeakとRMSの差。ダイナミックレンジの広さを表します。

## 操作方法

### Start Metering

測定を開始します。グラフの描画と統計の計算が始まります。

### 各種リセット

* **Reset Peaks**: レベルメーターのピークホールド表示をリセットします。
* **Reset Stats**: LUFS統計、ピークホールド、ピーク分布とイベント履歴、取得異常のラッチをリセットします。リセット境界でフィルター履歴も初期化します。停止中の保持結果も消去できます。

### Target LUFS

ターゲットとするラウドネスレベルを設定します。この値は以下の箇所に反映されます：

* **Statistics タブ**: Integrated LUFS との差分（Target Offset）の計算に使用されます。
* **Level Meter**: Integrated バーの色が、このターゲット値を基準に変化します（ターゲット付近で緑色、超過すると赤色など）。
* **Graph タブ**: グラフ上のターゲットを示す点線の位置がこの設定値に移動します。

### Show SPL

チェックを入れると、RMSレベルメーターの単位を「dB SPL」に切り替えます（事前にSettingsウィジェットでSPL校正が必要です）。LUFS値は常にdBFSベース（LUFS）で表示されます。

## グラフと統計

### Statistics タブ

各指標の現在値（Current）、最小値（Min）、最大値（Max）、平均値（Avg）を表で確認できます。

* **Target Offset**: 設定された Target LUFS と、現在の Integrated LUFS の差分を表示します。「+」はターゲットより大きい（うるさい）こと、「-」は小さい（静か）ことを示します。

### Graph タブ

Momentary（オレンジ）とShort-term（青）のラウドネス変化を時系列グラフで表示します。

* **点線**: 設定された Target LUFS を示す基準線です。
* これを目安に、楽曲や音声が目標とするラウドネス帯域に収まっているかを確認できます。

## 一般的なターゲットレベルの目安

* **テレビ放送**: -23 LUFS (Integrated) / -24 LKFS
* **YouTube**: -14 LUFS
* **Spotify**: -14 LUFS
* **CD / クラブミュージック**: -9 ~ -6 LUFS（音圧戦争により非常に高い場合があります）

## True Peak測定

True Peakは4倍FIR補間で推定し、入力10サンプル分の遅延があります。コールバック間でフィルター履歴を保持し、入力の不連続時に初期化します。BS.1770適合を保証する測定ではありません。内部ループバックは出力量子化前の信号を測るため、実機DACのヘッドルームを確認する用途には使えません。

## ピーク分布とクリッピングプロファイル

**ピークしきい値**は−60～+6 dBFS（初期値−1 dBFS）に設定できます。しきい値と等しい振幅もカウントします。フルスケール到達の調査には0 dBFS、ヘッドルームの調査には負の値を使用します。超過はデジタル信号のレベル情報であり、実機のクリッピングを証明するものではありません。

* **ピーク分布**: プロファイルのリセット以降のTrue Peak分布を左右独立に集計します。各入力フレームの4補間位相とサンプル振幅の最大値を、各チャンネルにつき1回加算します。−60～+6 dBTPを1 dB刻みとし、両端のビンには範囲外の値を含めます。無音は下端ビンに含まれます。縦軸はフレーム数であり、割合やコールバック最大値の回数ではありません。
* **SP / TPフレーム数**: チャンネルごとに、設定しきい値以上の入力フレーム数を示します。SPはサンプル振幅、TPは補間包絡線を使用します。モノラルはLのみを集計し、Rは表示しません。3チャンネル以上の入力は先頭の2チャンネルのみが対象です。
* **最長SP / TP**: しきい値以上の状態が連続した最長時間です。進行中の区間も含みます。連続フレーム数を取得サンプルレートで割り、ミリ秒で表示します。分解能は入力1フレームであり、4倍補間点ごとの継続時間ではありません。しきい値未満のフレームで区間が終了します。ヒステリシスやホールドオフはありません。
* **ピークイベント**: 左右のSPとTPを別々のレーンに表示します。丸印がSP、三角印がTPです。横軸はプロファイルリセットからの時間です。イベント総数は超過区間の開始回数で、フレーム数とは区別します。FIR遅延を補正し、両レーンを入力サンプル時刻に揃えます。進行中の区間や停止・欠損で切られた区間は、途中までの観測です。

イベント表示は進行中を含め最大512件です。古い記録の破棄数を表示し、累積回数と最長時間の集計は継続します。ヒストグラムは各チャンネル68ビンの固定メモリを使用します。古いイベント表示の破棄だけでは、累積統計は無効になりません。

しきい値超過の表示は、新しいプロファイルを開始するまで保持します。**Stop Metering**は受け付け済みの処理とFIR遅延中の入力10フレームを処理し、結果を保持します。補間用の追加ゼロは集計しません。**Start Metering**は新しいセッションを開始します。**Reset Peaks**はピークホールドだけ、**Reset Stats**は測定全体をリセットします。しきい値を変更するとピークプロファイルを即座に新規開始しますが、積分ラウドネスは保持します。過去の回数に新しいしきい値を付け直すことはありません。

データ欠損、不正・非有限入力、チャンネル数やサンプルレートの変更、キューあふれ、処理失敗は、理由とともに**不完全**としてラッチします。継続時間は既知の欠損をまたぎません。影響を受けた統計は部分的な観測として扱います。Reset Statsまたは再開始で異常履歴を消去でき、継続中の異常は再検出します。取得サンプルレートの変更後は、測定を再開始して新しいレートを適用してください。コンパクト表示でも状態とチャンネル別要約は残り、分割表示では読み出しとグラフが表示ウィンドウにまとまります。

### 処理上限

ヒストグラムとイベント集計はワーカーで処理します。音声コールバックは既存のTrue Peak補間を再利用し、事前確保した境界付きメールボックスへコピーします。ワーカーやGUIのロックを待ちません。リセットや統計更新が取得ロックを保持している場合は、そのブロックをスキップして欠損を記録します。メールボックスは最大32ブロック、各65,536フレーム（予約サンプル領域64 MiB）です。あふれた場合は新しいプロファイル入力を破棄し、元のサンプル時刻を保持します。それより大きいコールバックは不完全として拒否します。二乗前に10¹² FSを超える危険な振幅を拒否しますが、通常の0 dBFS超過はそのまま保持します。これらのソフトウェア上限は、すべての機器でのリアルタイム性能を保証するものではありません。
