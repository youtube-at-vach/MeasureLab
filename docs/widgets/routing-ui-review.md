# Routing UI 視覚評価記録

2026-09-07。配線設定をRoutingへ集約する改修について、実装担当とは別の視覚評価サブエージェントが、
実際のQtウィジェットのスクリーンショットを3回評価し、指摘に基づいて2回改善しました。

## 評価条件

同じ5画面を各回で比較しました。表示サイズは1080×690 px、macOSのQt既定フォントです。

- 英語・ライト：仮想VSTのステレオ測定
- 日本語・ライト：DUTのチャンネル設定を展開
- 英語・ライト：物理入力と物理出力
- 日本語・ダーク：仮想VSTのステレオ測定
- 英語・ライト：測定L＝VST出力、R＝Dry参照

プラグイン名とデバイスは表示確認用の構成例です。実デバイス・実プラグインは起動していません。
サブエージェントは画像から読み取れる情報だけを採点し、内部実装から意味を補完しない条件としました。
点数は一定の基準によるモデル評価であり、利用者による理解度試験や統計的な測定結果ではありません。

## 採点と改善

| 項目（各10点） | 初回 | 改善1 | 改善2・最終 |
| --- | ---: | ---: | ---: |
| 信号の出所と行先 | 6 | 8 | 8 |
| VST経路とDry分岐の理解 | 5 | 9 | 9 |
| 操作箇所の発見性 | 8 | 8 | 9 |
| 状態と無効理由 | 6 | 8 | 8 |
| 視認性・密度 | 7 | 8 | 9 |
| **合計** | **32 / 50** | **41 / 50** | **43 / 50** |

初回では、モニターの分岐元が独立したフォームから追いにくく、VST／Dryの測定L/Rへの割当も展開しないと分かりませんでした。
改善1で、選択した分岐元に「↓ モニター出力」と状態を表示し、下段の「↳ モニター出力」と対応付けました。
測定L/Rの割当を図中へ追加し、Dryが同じ発生信号の分岐であること、待機が信号待ちであることを明示しました。
矢印にも幅を確保し、文字サイズを拡大しました。

改善2では、設定を開くチェックボックスを矢印付きの「チャンネル設定を表示」ボタンへ変更しました。
ダークテーマでモニターのチェック枠を見つけやすくし、物理I/Oの処理カードに現在のStereo／Left／Rightを表示しました。
最終評価では、対象5画面で主目的を妨げる必須改善は残っていないと判定されました。

## 最終画面と残る制約

[物理I/O](../assets/routing/en-light.png)、[仮想VST・ダーク](../assets/routing/ja-dark.png)、
[チャンネル設定を展開](../assets/vst_dut/routing-ja.png)をマニュアルの画面例として更新しています。

モニター分岐は連続した接続線ではなく、両端の名称と矢印の対応付けを併用しています。
信号の開始操作は各測定器・信号発生器で行うため、この画面だけでは完結しません。
Remote、有効なモニターの再生状態、操作後の更新、キーボード操作は今回の静止画採点の対象外です。
Remote入力専用表示、モニター有効化・音量・待機、配線変更による停止、配線編集の測定中ロック、無音チャンネル、
状態同期は自動テストで確認しています。

## 再現と検証

画面例は次のコマンドで生成できます。音声デバイスやVSTをロードせず、オフスクリーンで描画します。

```bash
./.venv/bin/python scripts/capture_routing_screenshots.py --output-dir /tmp/measurelab-routing-review
```

関連GUI・ルーティング・VST・MainWindowテストは152件成功、実VSTを必要とする3件は未指定のためスキップしました。
全9言語のレイアウト上限チェック、Ruff、Mypy、翻訳キーと未翻訳チェック、変更ドキュメントのMarkdown lintも確認しています。

音声処理エンジンの定型経路は変更していません。VSTは引き続き仮想オーディオの発生信号に適用され、
物理／Remote入力にVSTを挿入する機能や任意の自由配線は追加していません。
