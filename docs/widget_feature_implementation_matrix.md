# ウィジェット共通機能 実装状況マトリクス

調査日: 2026-08-14

## 調査の目的と範囲

各測定ウィジェットに個別導入されている共通 UI 機能を一覧化し、実装漏れ、
テスト漏れ、ドキュメントとの不一致を発見しやすくするための資料です。

対象は `ALL_MODULE_KEYS` と `MODULE_REGISTRY` に登録されている 42 モジュールです。
Welcome と Settings は通常のモジュール用ラッパーを使用しないため、表から除外しています。
Nonlinear Response Analyzer は実験的モジュールですが、実装漏れを見逃さないため表に含めています。

判定は次のコード上の事実に基づきます。

- 全モジュール共通機能: `DetachableWidgetWrapper` から常に提供されるか
- コンパクトモード: `CompactableWidgetInterface` とレイアウト更新処理があるか
- 2 窓分割: `SplittableWidgetInterface` と表示、操作、復元の 3 処理があるか
- 比較送信: `ComparableWidgetInterface` と比較データ生成処理があるか
- テスト: 対象機能を直接操作する自動テストが存在し、今回の調査で成功したか

## ステータスの見方

| 記号 | 意味                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------- |
| 共✓  | 共通ラッパーで実装済み。関連する共通テストも成功                                                        |
| 共△  | 共通ラッパーで実装済みだが、その操作を直接確認する自動テストが見当たらない                              |
| 個✓  | ウィジェット側で個別実装済み。対象テストも成功                                                          |
| 個△  | ウィジェット側で個別実装済みだが、直接確認する対象テストが見当たらない                                  |
| 要   | 個別機能は未実装。適用対象外とは断定できないため、必要性を個別に判断する候補                            |
| 外A  | 対象外。操作主体で、分離または表示専用化する独立した表示・結果領域がない                                |
| 外B  | 対象外。比較対象が表、単一数値、状態表示、2D 画像で、現在の Plot Comparer が扱う 1D/XY トレースではない |
| 外C  | 対象外。Plot Comparer 自身は比較データの受信・表示先であり、送信元にはしない                            |
| 外D  | 対象外。人間のレビューにより、実用度の観点から比較送信はひとまず実装不要と判断されたもの                |
| 外E  | 対象外。人間のレビューにより、実用度の観点からコンパクトモードはひとまず実装不要と判断されたもの        |
| 外F  | 対象外。人間のレビューにより、実用度の観点から 2 窓分割はひとまず実装不要と判断されたもの               |

`要` は実装推奨を意味しません。表示部と操作部を安全に分けられるか、コンパクト表示に
残すべき情報が明確か、比較する利用場面があるかを確認してから対応可否を決める必要があります。

外A〜Cの対象外判定は、コード上の UI 構造と現在の比較データ形式から明確に判断できるものに
限定しています。外D〜Fはこれらとは別に、人間のレビューにより実用度を確認し、対象機能は
ひとまず実装不要と判断したものです。外Dは比較送信、外Eはコンパクトモード、外Fは 2 窓分割に
適用しています。プロットがなくても、Loopback Finder の結果表や Timecode Monitor の大型表示の
ように独立した閲覧価値がある領域は対象外にしていません。また、すでに実装済みの機能は必要性を
再評価せず、実装状況をそのまま記録しています。

モジュール別マトリクスの「完了」は、2 窓分割、コンパクト、比較送信のすべてが実装済みまたは
対象外となり、`要` が残っていないことを示します。全モジュール共通のログに直接テストがないことは、
個別ウィジェットの完了判定には含めません。内部ペインはウィジェット固有のレイアウト実装であるため、
共通機能の評価対象から除外しています。

## ウィンドウ状態と操作仕様

共通ラッパーには次の 3 状態があります。

| 状態    | 内容                                         | 対象                         |
| ------- | -------------------------------------------- | ---------------------------- |
| State A | メインウィンドウ内の通常表示                 | 全モジュール                 |
| State B | ウィジェット全体を一つの独立ウィンドウに分離 | 全モジュール                 |
| State C | 表示部と操作部を二つの独立ウィンドウに分割   | 2 窓分割対応の 10 モジュール |

実装済みの状態遷移は `A → B`、`B → A`、`A → C`、`B → C`、`C → A` です。
State B から State C へ移る場合は、いったん内部的に再接続してから 2 窓へ分割します。

コンパクトボタンは対応ウィジェットの共通ヘッダーに常時作成されますが、State A では無効です。
State B または State C で有効になり、再接続時には通常表示へ自動的に戻ります。独立ウィンドウでは
`C` キーでも切り替えられます。State C のコンパクト化対象は表示側ウィンドウです。

スクリーンショットは State C のとき表示側パネルを対象にし、それ以外ではウィジェット全体を対象にします。
Logs はモジュール固有ログではなく、共通のシングルトンログビューアを開きます。

## メインウィンドウ側の関連共通機能

モジュール別マトリクス外ですが、次の共通機能も実装されています。

- Menu Only: コンテンツ領域と通常ステータスバーを隠し、サイドバー幅まで縮小
- Menu Only からの分離起動: モジュールをダブルクリックすると State B で開く
- グローバル出力先: Physical、Internal Loopback、Loopback + Physical を共通選択
- 遅延ロード: 選択時にモジュールとウィジェットを生成し、同じ共通ラッパーで包む
- アクティビティ表示: 実行中モジュールをサイドバーで強調し、分離状態をツールチップへ表示

## 実装漏れ防止の観点で見つかった課題

### 優先度高: 自動検出できない実装・資料のずれ

1. 機能対応表の正本がありません。現在はラッパーが `isinstance()` または `hasattr()` で
   実行時に機能を推定します。そのため、新規ウィジェットでインターフェースや必要メソッドを
   一つ実装し忘れても、ボタンが表示されないだけで気付きにくい構造です。
2. `MODULE_REGISTRY` の全モジュールに対して、期待する機能宣言と実装を照合する契約テストがありません。
3. Transmission Analyzer のコンパクトモード、Distortion Analyzer と Lock-in Amplifier の比較送信には
   直接テストが見当たりません。
4. Logs ボタンからログビューアを開く共通操作には直接テストが見当たりません。

### 優先度中: ウィンドウ状態の扱い

1. サイドバーの状態表示は `is_detached` だけを見ており、State C の `is_split` を表示しません。
2. Menu Only 中のダブルクリック処理は State B の既存ウィンドウを前面化できますが、State C の
   2 ウィンドウを前面化する分岐がありません。分割済みモジュールをダブルクリックしても、
   `detach()` が何もせず終了するため、見失った分割ウィンドウを呼び戻せません。
3. 分離状態、分割状態、各独立ウィンドウの位置とサイズを設定へ永続化する処理はありません。
   アプリ再起動後は State A から始まります。

### 優先度中: 既存マニュアルとの不一致・記載漏れ

## 次に追加すると効果が高い仕組み

1. モジュールごとの期待機能と対象外理由を宣言する `WidgetCapabilities` を一か所に置く
2. `MODULE_REGISTRY` の全クラスを走査し、対象機能の宣言とインターフェース実装を照合するテストを追加する
3. この表の実装状態、`要`、対象外理由を宣言データから自動生成し、手書きの表とコードの乖離をなくす
4. 未テストの 7 個別機能と Logs 共通操作へテストを追加する
5. State C をサイドバー表示と Menu Only の前面化処理へ追加する
6. 個別マニュアルでは曖昧な「など」を避け、対応機能を明示する

## 検証記録

今回、共通機能に関連する GUI テスト 17 ファイルをまとめて実行し、`113 passed` を確認しました。
静的確認だけでなく、コンパクト切り替え、分割と再接続、State B から State C への遷移、
分割中のスクリーンショット、比較データ生成を含みます。

ただし、OS のウィンドウマネージャーを使った手動操作、複数モニター配置、フルスクリーン、
アプリ再起動をまたぐ動作は今回の自動テスト範囲に含まれません。
