## 概要

更新日: 2026-08-24

## 調査の目的と範囲

各測定ウィジェットに個別導入されている共通 UI 機能を一覧化し、実装漏れ、
テスト漏れ、ドキュメントとの不一致を発見しやすくするための資料です。

対象は `ALL_MODULE_KEYS` と `MODULE_REGISTRY` に登録されている 42 モジュールです。
Welcome と Settings は通常のモジュール用ラッパーを使用しないため、表から除外しています。
Nonlinear Response Analyzer は実験的モジュールですが、実装漏れを見逃さないため表に含めています。

判定は次のコード上の事実に基づきます。

- 全モジュール共通機能: `DetachableWidgetWrapper` から常に提供されるか
- コンソール主操作: `WidgetCapabilities.console_primary_action` の宣言先が、開始／停止を一つの
  チェック可能ボタンで切り替える実装と一致するか
- コンパクトモード: `WidgetCapabilities` の宣言と `CompactableWidgetInterface`、レイアウト更新処理が一致するか
- 2 窓分割: `WidgetCapabilities` の宣言と `SplittableWidgetInterface`、表示、操作、復元の 3 処理が一致するか
- 比較送信: `WidgetCapabilities` の宣言と `ComparableWidgetInterface`、比較データ生成処理が一致するか
- テスト: 対象機能を直接操作する自動テストが存在し、今回の調査で成功したか

| 記号 | 意味                                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------- |
| 共✓  | 共通ラッパーで実装済み。関連する共通テストも成功                                                        |
| 共△  | 共通ラッパーで実装済みだが、その操作を直接確認する自動テストが見当たらない                              |
| 個✓  | ウィジェット側で個別実装済み。対象テストも成功                                                          |
| 個△  | ウィジェット側で個別実装済みだが、直接確認する対象テストが見当たらない                                  |
| 要   | 個別機能は未実装。適用対象外とは断定できないため、必要性を個別に判断する候補                            |
| 外A  | 対象外。操作主体で、分離または表示専用化する独立した表示・結果領域がない                                |
| 外B  | 対象外。比較対象が表、単一数値、状態表示、2D 画像で、現在の Plot Comparer が扱う 1D/XY トレースではない |
| 外C  | 対象外。Plot Comparer 自身は比較データの受信・表示先であり、送信元にはしない                            |
| 外D  | 対象外。人間のレビューにより、実用度の観点から比較送信はひとまず実装不要と判断されたもの                |
| 外E  | 対象外。人間のレビューにより、実用度の観点からコンパクトモードはひとまず実装不要と判断されたもの        |
| 外F  | 対象外。人間のレビューにより、実用度の観点から 2 窓分割はひとまず実装不要と判断されたもの               |
| 外G  | 対象外。継続動作を一つの開始／停止トグルで操作するモジュールではない                                    |

`要` は実装推奨を意味しません。表示部と操作部を安全に分けられるか、コンパクト表示に
残すべき情報が明確か、比較する利用場面があるか、コンソールから操作すべき主動作かを確認してから
対応可否を決める必要があります。

外A〜Cの対象外判定は、コード上の UI 構造と現在の比較データ形式から明確に判断できるものに
限定しています。外D〜Fはこれらとは別に、人間のレビューにより実用度を確認し、対象機能は
ひとまず実装不要と判断したものです。外Dは比較送信、外Eはコンパクトモード、外Fは 2 窓分割に
適用しています。プロットがなくても、Loopback Finder の結果表や Timecode Monitor の大型表示の
ように独立した閲覧価値がある領域は対象外にしていません。また、すでに実装済みの機能は必要性を
再評価せず、実装状況をそのまま記録しています。

外Gはコンソール主操作だけに適用します。ファイルの読み込みや一回限りの処理、複数の再生／録音操作など、
単一の開始／停止トグルへ安全に集約できないモジュールを対象外としています。

モジュール別マトリクスの「完了」は、2 窓分割、コンパクト、比較送信、コンソール主操作のすべてが実装済みまたは
対象外となり、`要` が残っていないことを示します。全モジュール共通のログは More メニューから開く
共通経路の直接テストで確認します。内部ペインはウィジェット固有のレイアウト実装であるため、
共通機能の評価対象から除外しています。

## ウィンドウ状態と操作仕様

共通ラッパーには次の 3 状態があります。

| 状態    | 内容                                         | 対象                         |
| ------- | -------------------------------------------- | ---------------------------- |
| State A | メインウィンドウ内の通常表示                 | 全モジュール                 |
| State B | ウィジェット全体を一つの独立ウィンドウに分離 | 全モジュール                 |
| State C | 表示部と操作部を二つの独立ウィンドウに分割   | 2 窓分割対応の 11 モジュール |

実装済みの状態遷移は `A → B`、`B → A`、`A → C`、`B → C`、`C → A` です。
State B から State C へ移る場合は、いったん内部的に再接続してから 2 窓へ分割します。

コンパクトボタンは対応ウィジェットの共通ヘッダーに常時作成されますが、State A では無効です。
State B または State C で有効になり、再接続時には通常表示へ自動的に戻ります。独立ウィンドウでは
`C` キーでも切り替えられます。State C のコンパクト化対象は表示側ウィンドウです。

スクリーンショットは State C のとき表示側パネルを対象にし、それ以外ではウィジェット全体を対象にします。
Logs はモジュール固有ログではなく、共通のシングルトンログビューアを開きます。

計測コンソールでは、対応する 30 モジュールの開始／停止ボタンをドックのタイトルバーへ再掲します。
操作状態、ラベル、ツールチップ、再生／停止アイコンは元ボタンと同期します。ボタン名の推測には依存せず、
`WidgetCapabilities.console_primary_action` に宣言されたチェック可能ボタンだけを公開します。

## メインウィンドウ側の関連共通機能

モジュール別マトリクス外ですが、次の共通機能も実装されています。

- Menu Only: コンテンツ領域と通常ステータスバーを隠し、サイドバー幅まで縮小
- Menu Only からの分離起動: 未分離のモジュールをダブルクリックすると State B で開く
- Menu Only からの再表示: State B は独立ウィンドウ、State C は表示・操作の両ウィンドウを前面化
- グローバル出力先: Physical、Internal Loopback、Loopback + Physical を共通選択
- モジュール生成: 通常起動ではスプラッシュ表示中に全対象モジュールを事前ロードし、未生成の場合は
  選択時に遅延ロードする。どちらの経路でも同じ共通ラッパーで包む
- アクティビティ表示: 実行中モジュールをサイドバーで強調し、State B／State C をツールチップへ表示

## 実装漏れ防止の仕組み

### 能力宣言の正本

- `src/gui/module_registry.py` の `ModuleRegistration` と `WidgetCapabilities` が、遅延ロード情報、
  対応機能、対象外理由の正本です。
- 共通ラッパーはメインアプリから能力宣言を受け取り、宣言とインターフェース実装が異なる場合は
  明示的なエラーにします。コンソール主操作も宣言先がチェック可能ボタンか検証します。
  `hasattr()` による暗黙の機能推定は使用しません。
- 契約テストは `ALL_MODULE_KEYS` の全 42 モジュールについて、登録漏れ、対応数、インターフェース、
  必須メソッドのオーバーライドを検査します。
- 本文書のサマリーとモジュール別マトリクスは `scripts/generate_widget_feature_matrix.py` で生成します。
  `--check` により宣言と文書のずれを検出できます。

### 直接操作テスト

- Transmission Analyzer のコンパクト切り替えを共通ラッパー経由で確認します。
- Distortion Analyzer と Lock-in Amplifier の比較データ生成を確認します。
- More メニューの Logs アクションが共通ログビューアを表示し、前面化することを確認します。
- State C の2ウィンドウ前面化とサイドバー表示を確認します。
- コンソールの共通タイトルバー操作、元ボタンの有効／無効状態との同期、Frequency Counter の
  `run_btn` 操作を確認します。全モジュール契約テストでは、30 モジュールの宣言先が実在する
  チェック可能ボタンであることと、残る 12 モジュールの対象外判定を確認します。

### マニュアル同期

- Frequency Counter、Lock-in Spectrum Finder、Event Detector、Timecode Monitor、
  Stereo Alignment Monitor、Transmission Analyzer は、対応する共通機能を日英両版で明記します。
- Detachable Wrapper は Compact ボタンの有効条件、More メニュー内の Send to Comparer、プラットフォーム別の
  スクリーンショット既定保存先、State C の再表示方法を日英両版で説明します。

## 残る検討事項

分離／分割状態と各ウィンドウの位置・サイズは永続化していません。アプリ再起動後は安全で予測可能な
State A から始まります。前回状態を復元する場合は、ディスプレイ構成変更による画面外配置の補正と、
State A を既定とする安全性のどちらを優先するか、製品仕様を決めてから実装する必要があります。
